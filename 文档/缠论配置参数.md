# 缠论配置参数完整说明

> 适用代码基线：2026-10-25（`chan-standard-bsp` / `bsp1` / `bsp2` / `bsp3` 系列改造之后）
> 来源文件：`ChanAnalyse/ChanConfig.py`（主配置与档位预设）、`ChanAnalyse/BuySellPoint/BSPointConfig.py`（买卖点）、`ChanAnalyse/Bi/BiConfig.py`（笔）、`ChanAnalyse/Seg/SegConfig.py`（线段）、`ChanAnalyse/ZS/ZSConfig.py`（中枢）
> 全部默认值均由代码读取，非文档推断。

---

## 一、配置入口与机制

### 1.1 用法

```python
from ChanAnalyse.ChanConfig import CChanConfig

config = CChanConfig({
    "bsp_preset": "standard",
    "divergence_rate": 0.9,
    "macd_algo-sell": "area",     # 后缀覆盖：仅卖出侧
})
```

### 1.2 严格校验：未知 key 直接抛异常

`ConfigWithCheck` 包装器会消费已识别的 key，构造末尾 `check()` 检查残留。**任何拼写错误的 key 都会抛 `CChanException(PARA_ERROR)`**，不会静默忽略。

```
CChanConfig({"divergence_rat": 0.9})
→ CChanException: invalid CChanConfig: divergence_rat
```

### 1.3 档位预设（`bsp_preset`）

只影响买卖点参数。展开顺序是**「默认 → 预设 → 用户显式 key」**，因此单项覆盖总是有效：

```python
CChanConfig({"bsp_preset": "legacy", "bsp1_zero_axis": True})
# 结果：divergence_rate=inf、bsp1_trend=False（预设生效）
#       但 bsp1_zero_axis=True（显式 key 覆盖预设）
```

| 预设 | 用途 |
|---|---|
| `standard`（默认） | 改造后的标准口径，完整实现缠论要素 |
| `legacy` | 一键回退改造前的行为，用于复现历史输出与等价性对照 |

`legacy` 实际改写的 17 个参数（下表末两行按用途分组列出）：

| 参数 | standard | legacy |
|---|---|---|
| `divergence_rate` | `0.9` | `inf`（相当于关闭背驰力度约束） |
| `min_zs_cnt` | `2` | `1` |
| `bsp1_trend` | `True` | `False` |
| `bsp1_new_extreme` | `True` | `False` |
| `bsp1_dif_div` | `True` | `False` |
| `bsp1_zero_axis` | `True` | `False` |
| `bsp1_zs_extend_to_seg_end` | `False` | `True` |
| `bsp2_retrace_zs` | `False` | `False`（显式写入，防未来漂移） |
| `bsp2s_require_zs` | `True` | `False` |
| `bsp2s_rate_mode` | `amp` | `disp` |
| `bsp3b_mode` | `standard` | `legacy` |
| `bsp3_peak_on_breakout` | `True` | `False` |
| `bsp1_downgrade_to_pz` / `bsp1_force_scope` / `bsp1_qjt` | `True`/`swing`/`False` | `False`/`bi`/`False`（防御性显式写入） |
| `macd_algo` / 极值口径 | `full_area` / 宽松 | `peak` / 宽松（档位等价的必要条件） |

### 1.4 后缀覆盖：按方向 / 级别分侧配置

| 后缀 | 作用范围 |
|---|---|
| 无后缀 | 笔级别买卖点，买 + 卖两侧 |
| `-buy` | 仅笔级别买入 |
| `-sell` | 仅笔级别卖出 |
| `-seg` | 线段级别，买 + 卖两侧 |
| `-segbuy` | 仅线段级别买入 |
| `-segsell` | 仅线段级别卖出 |

```python
{"macd_algo": "peak", "macd_algo-sell": "area"}
# 买侧 PEAK（显式覆盖默认的 FULL_AREA），卖侧 AREA
```

**后缀与枚举校验的关系**：后缀覆盖走 `CPointConfig.set()`，**不经过** `_check_choice` 白名单校验。也就是说 `{"bsp3b_mode-sell": "xxx"}` 不会在构造期报错，非法值要等到判定期才暴露。需要分侧配置枚举参数时请自行确保取值合法。

> 历史缺陷（已于 2026-10-25 修复）：`set()` 曾用 `exec(f"self.{k} = {v}")` 拼接赋值，字符串值会被**二次解释**——`"legacy"` 变为 `NameError`，`"all"` 更危险，会静默绑定到 Python 内置函数 `all` 而不报错。现改为 `setattr`。

### 1.5 无穷大写法

配置值可用 Python 的 `float("inf")` 表示「无条件通过」；字符串 `"inf"` 也会被 `_parse_inf` 转换。`divergence_rate=inf` 等价于关闭背驰约束（`legacy` 档即如此）。

## 二、笔配置（`CBiConfig`）

| 参数 | 默认 | 取值 | 含义与作用 |
|---|---|---|---|
| `bi_algo` | `normal` | `normal` / `fx` | 笔算法。`normal` 需满足合并 K 线数量跨度检查；`fx` **跳过跨度检查**，只看分型是否成立，产生的笔更多、更碎 |
| `bi_strict` | `True` | `bool` | 严格模式。`True` 要求至少 4 根合并 K 线；`False` 放宽到 3 根（含 3 根原始 K 线） |
| `bi_fx_check` | `strict` | `strict`/`loss`/`half`/`totally` | 顶底分型合法性检查口径，严格程度递增：`loss`（只比中间元素）< `half`（比顶分型前两元素 + 底分型后两元素）< `strict`（底分型三元素最低点须低于顶分型三元素最低点）< `totally`（底分型最高点须低于顶分型最低点）。**改这个会显著改变笔的数量** |
| `gap_as_kl` | `False` | `bool` | 跳空是否算作一根 K 线。`True` 让笔更容易形成（缺口计入跨度） |
| `bi_end_is_peak` | `True` | `bool` | 笔端点是否必须是极值点（中间 K 线不能越过端点） |
| `bi_allow_sub_peak` | `True` | `bool` | 是否允许次高/次低点作为笔端点。`False` 时端点必须严格创新高/新低 |

> **默认值注意**：`CBiConfig` 类签名的默认是 `bi_fx_check="half"`、`gap_as_kl=True`，但 `CChanConfig` 传给它的实参是 `"strict"` 和 `False`。**以 `CChanConfig` 的值为准**（上表已是实际生效值）。

## 四、中枢配置（`CZSConfig`）

| 参数 | 默认 | 取值 | 含义与作用 |
|---|---|---|---|
| `zs_combine` | `True` | `bool` | 是否合并相邻中枢（区间有重叠时并为一个更大中枢） |

## 五、运行模式（`CChanConfig` 顶层）

| 参数 | 默认 | 含义与作用 |
|---|---|---|
| `trigger_step` | `False` | **批量 / 步进两种模式的总开关。** `False` = 加载全部数据后一次性算完；`True` = `CChan` 变为生成器，每根新 K 线产出一个快照，用于回测与动画回放。**落库链路（`WebAPI/incremental_engine`）恒为 `True`** |

## 八、买卖点通用配置

买卖点配置同时构造两份：`bs_point_conf`（笔级别）与 `seg_bs_point_conf`（线段级别）。两者取同一份参数，**唯一差异是线段级别的 `bsp1_only_multibi_zs` 被强制设为 `False`**（线段级别不要求多笔中枢）。

| 参数 | 默认 | 含义与作用 |
|---|---|---|
| `bs_type` | `"1,1p,2,2s,3a,3b"` | 要计算的买卖点类型（逗号分隔）。合法值：`1`（一买）、`1p`（盘整背驰）、`2`（二买）、`2s`（类二）、`3a`（三买A，中枢在下一条线段）、`3b`（三买B，中枢在本线段）。**收窄此项是提升性能最直接的手段** |
| `divergence_rate` | `0.9` | 背驰率阈值。离开段力度 / 进入段力度 的比值上限；`< 1` 才构成背驰。`inf` = 关闭该约束（`legacy` 档） |
| `min_zs_cnt` | `2` | 一买要求的最少中枢数，**只数数量、不判方向**；取值上限 **2**（`3` 及以上会被 `validate_config()` 拒绝）。`bsp1_trend=True` 时本项**失效**——趋势判据恒要求至少两个多笔中枢，填 1 或 2 均不再额外过滤；只有关闭趋势判据（如 `legacy` 档）时才真正生效。默认 `2`，`legacy` 档为 `1` |
| `bsp1_only_multibi_zs` | `True` | 一买是否只认「多笔中枢」（排除一笔中枢）。线段级别强制为 `False` |
| `macd_algo` | `full_area`（可多选：如 `full_area,diff_peak`） | 是否背驰的技术指标，见 §九。勾选多项时**要求同时满足**（AND）；`legacy` 档为 `peak` |
| `bs1_peak` | `True` | 一买是否要求价格创极值（离开段创新低/新高）。「创新极值」是**宽松口径**：价格等于前面的低点也算创出新低（双底/双顶不会被拦下）。该口径已固化，无独立开关（原 `bs1_peak_strict` 已删除） |
| `max_bsp2s_lv` | `None` | 类二买卖点的最大层级限制；`None` = 不限 |
| `bsp_preset` | `standard` | 档位预设名，见 §1.3。**仅用于文档与诊断标注，不参与判定逻辑**——它已经通过展开改写上面的各项值 |

> **`min_zs_cnt` 与 `bsp1_trend` 的分工（易混淆）**
>
> | | `min_zs_cnt` | `bsp1_trend` |
> |---|---|---|
> | 判什么 | 只数中枢个数（`seg.get_multi_bi_zs_cnt()`） | 最后两个多笔中枢是否**依次下移/上移** |
> | 消费点 | `BSPointList.cal_single_bs1point`（`zs_cnt >= min_zs_cnt`） | `BSPJudgement.check_trend`（`multi[-2]` / `multi[-1]`，写死 2 个） |
> | 失败落点 | 全部判据通过但中枢数不够 → 仅**结构性候选**，不落库 | `reason=='trend'` → 可命中**降级路由**，以 `T1P` 落库 |
>
> 两者都不判断「3 个中枢是否同向」——`bsp1_trend` 只看最后两个。因此在
> `bsp1_trend=True` 的默认配置下，`min_zs_cnt` 取 1 或 2 都是 **no-op**（趋势判据
> 恒保证 ≥2 个多笔中枢），这也是它上限被收到 2 的原因：3 及以上会构成
> 「至少 3 个中枢」这一趋势判据表达不了的约束，但那仍是纯计数而非趋势定义。

### 8.1 类型间跟随关系

| 参数 | 默认 | 含义与作用 |
|---|---|---|
| `bsp2_follow_1` | `True` | 二买是否必须跟在一买之后。`False` 时允许独立成立的二买 |
| `bsp3_follow_1` | `True` | 三买是否必须跟在一买之后 |
| `bsp3_follow_1_mode` | `sure` | 三买跟随一买的口径。`sure` = 查**已成立**的一买集合（默认）；`candidate` = 查全部结构性候选一买（更宽松） |
| `bsp2s_follow_2` | `False` | 类二是否必须跟在成立的二买之后 |

## 九、力度算法（`macd_algo`）

`CBi` 与 `CSeg` 共用同一套实现（`ChanAnalyse/Math/Metric.py`），线段级别此前只支持 `slope`/`amp`，现已补齐。

| 取值 | 力度口径 | 缠论对应 |
|---|---|---|
| `full_area`（默认） | 整段柱体面积（正负柱相互抵消） | 整段动能对比：对「急跌赶底」不钝感——跌幅大、时间短的离开段单根柱子天然更深，`peak` 会把整段动能已衰竭误判为不背驰 |
| `area` | 同向柱面积（只累加同向柱） | 面积背驰 |
| `diff` | 柱体 `max - min` | 柱体高度差 |
| `diff_peak` | DIF（黄白线）极值 | DIF 背驰 |
| `slope` | 斜率 | 走势斜率 |
| `amp` | 振幅 | 价格振幅 |
| `amount` / `volumn` | 成交额 / 成交量 | 量能背驰 |
| `amount_avg` / `volumn_avg` | 上述的均值版 | 量能均值背驰 |
| `turnrate_avg` | 换手率均值 | 换手背驰 |
| `rsi` | RSI 值 | RSI 背驰 |

> **区间口径限制**：`bsp1_force_scope="swing"` 需要对**区间**求力度，而 `volumn` / `amount` / `volumn_avg` / `amount_avg` / `turnrate_avg` 没有区间版本，会自动退回单笔口径，并在特征里标记 `bsp1_force_scope_effective="bi_fallback"`。

> **多选（AND 语义）**：`macd_algo` 可勾选多项（配置字典里写列表，如 `["full_area", "diff_peak"]`）。多项时**全部指标都构成背驰才算背驰**；任一项不满足即不成立。报告的背驰率取各项中最保守（最大）的那个。返回值里 `macd_algo` 属性保持兼容形态——单项仍是枚举、多项是枚举列表；内核判据统一读 `macd_algos`（恒为列表）。区间口径按「**任一**指标支持区间即走 swing」判定，不支持区间的量能类在 swing 下各自退回单笔，不会把其它指标的粒度一起拉回单笔。

## 十、第一类买卖点（一买 / 一卖）

| 参数 | 默认 | 含义与作用 |
|---|---|---|
| `bsp1_trend` | `True` | **趋势前提**：要求至少两个依次下移（买）/上移（卖）的中枢。关闭后退化为「盘整背驰」口径 |
| `bsp1_trend_mode` | `strict` | 趋势判定口径。`strict` = 严格（中枢区间不重叠）；`overlap` = 允许区间重叠 |
| `bsp1_new_extreme` | `True` | 要求离开段创**趋势新低/新高**（不是仅创新低） |
| `bsp1_new_extreme_mode` | `trend_start` | 新低的比较起点。`trend_start` = 从趋势起点比；`prev_zs_in` = 与上一中枢进入笔比；`all` = 与全部历史比（线段内）；`level` = 与本级别此前**全部**同向笔比（跨线段边界，线段级别无全量笔列表时退回 `all` 并在特征 `new_extreme_mode_effective` 标明）。比较口径恒为宽松（相等极值算创新低） |
| `bsp1_dif_div` | `True` | 要求 DIF（黄白线）同步背驰 |
| `bsp1_zero_axis` | `True` | 要求 b/c 段之间 DIF 回抽过零轴（「零轴回抽」判据） |
| `bsp1_zs_extend_to_seg_end` | `False` | 是否仍要求中枢延伸到线段末笔。这是历史 4.8 条件，`standard` 档已关闭 |
| `bsp1_downgrade_to_pz` | `True` | 趋势前提不达标但背驰链路成立时，**降级为 T1P 登记**而非直接丢弃。降级点固定 `is_target_bsp=False`，不进已确认集合，也不作二买/三买的锚点 |
| `bsp1_force_scope` | `swing` | 力度比较的取值窗口。`swing` = 走势段（b 窗口 = 上一中枢结束笔+1 ~ 中枢进入笔；c 窗口 = 离开笔 ~ 线段末笔，整段聚合）；`bi` = 单笔（改造前口径） |
| `bsp1_qjt` | `False` | 区间套**特征**开关。开启后为一买候选计算「c 走势段内是否存在次级别同向已确认一买」，写入 `bsp1_qjt_hit` / `bsp1_qjt_sub_idx`。**这是特征不是判据**——不改变任何买卖点的成立性与数量 |
| `bsp1_qjt_depth` | `1` | 区间套递归深度。多层会成倍放大「子级确认滞后」导致的步进/批量口径分叉，默认收敛一层 |

---

## 十一、第二类买卖点（二买 / 二卖）

| 参数 | 默认 | 含义与作用 |
|---|---|---|
| `max_bs2_rate` | `0.9999` | 二买回调的最大回撤率。该约束在数学上同时保证「不破一买极值」。断言 `<= 1` |

二买判据：**已成立的一买 + 锚点后第 1 笔反向（回调）+ 振幅比 ≤ `max_bs2_rate`**。

### 11.1 类二买卖点（`2s`）

| 参数 | 默认 | 含义与作用 |
|---|---|---|
| `bsp2_retrace_zs` | `False` | 二买回调是否要求与中枢区间关联（`standard` 档关闭） |
| `bsp2s_require_zs` | `True` | 类二是否要求末端价格落在多笔中枢区间内 |
| `bsp2s_rate_mode` | `amp` | 类二回撤率的量纲。`amp` = 振幅口径（默认）；`disp` = 位移口径（改造前） |

### 11.2 T2 五轴阶梯参数（证据标注，不改成立性）

T2/T2S 候选点在 `bsp_index.ladder` 落五轴组合值 `P|S|C|K|T`（进度 → 佐证 → 确认 → 分型 → 时间）。

| 参数 | 默认 | 含义与作用 |
|---|---|---|
| `bsp2_confirm_window` | `2` | 确认轴考察窗口笔数，只能取 `1` 或 `2`。实证定标为 2（窗口 1 会把末端候选误判为 strong，窗口 2 标 `C0` 更保守） |
| `bsp2_confirm_level` | `strong` | 确认轴阈值口径。`strong` = 后续笔突破 `break_bi` 端点才算确认；`weak` = 收复振幅一半以上即算确认 |
| `bsp2_time_axis_strong` | `0.5` | 时间轴强档阈值：速度比 `v ≤ 该值` → `T3`（急涨缓跌、回调衰竭） |
| `bsp2_time_axis_weak` | `1.0` | 时间轴弱档阈值：`v > 该值` → `T1`（缓涨急跌）；中间为 `T2`。**必须满足 `0 < strong < weak`**，否则构造期抛异常 |

速度比定义：`v = (amp(回调笔)/amp(突破笔)) / (klu_cnt(回调笔)/klu_cnt(突破笔))`。

## 十二、第三类买卖点（三买A / 三买B）

| 参数 | 默认 | 含义与作用 |
|---|---|---|
| `bsp3_peak` | `False` | 三买是否要求「突破笔突破中枢内部极值」。**注意默认是 `False`（关闭）** |
| `bsp3_peak_on_breakout` | `True` | `bsp3_peak` 开启时的**判据对象**。`True` = 判突破笔（中枢离开笔），与文档语义一致；`False` = 判回抽笔（历史行为，且只在 T3A 生效） |
| `bsp3b_mode` | `standard` | T3B 判定档位。`standard` = 标准三买（离开笔真正突破 → 第一笔回抽 → 不回中枢）；`legacy` = 历史扫描（从一买笔+2 起每隔 2 笔扫，遇回中枢继续后扫——实测 11 个样本 0 个是「第一次回抽」） |
| `strict_bsp3` | `False` | 严格模式，要求中枢**紧邻**一买。T3A 判「进入笔 == 一买笔+1」，T3B 判「离开笔 == 一买笔」——**两分支条件不同是结构性必然**（中枢位置不同），不可统一 |
| `bsp3a_max_zs_cnt` | `1` | T3A 在「下一条线段」内最多检查前 N 个多笔中枢。断言 `>= 1` |

### 12.1 T3 四轴阶梯参数（证据标注，不改成立性）

T3A/T3B 候选点落四轴组合值 `S|C|K|T`，**无进度轴**——T3 判据链（锚定中枢 → 突破方向 → 第一次回抽 → 不回中枢）在回抽笔端点一次性全部可判，不存在「推进到一半」的中间态。

| 参数 | 默认 | 含义与作用 |
|---|---|---|
| `bsp3_confirm_window` | `2` | 确认轴考察窗口笔数，只能取 `1` 或 `2`。确认轴是缠论要素 E（回抽后趋势延续）的**事后确认层，不是成立判据** |
| `bsp3_confirm_level` | `strong` | 确认轴阈值口径。`strong` = 后续笔突破回抽笔端点 → `C3`；`weak` = 收复回抽幅度一半即算确认 |
| `bsp3_time_axis_strong` | `0.5` | 时间轴强档阈值：`v ≤ 该值` → `T3`（回抽衰竭）。参照笔是**突破笔**（`bi_list[bsp.idx-1]`），与 T2 的 `break_bi` 取值不同 |
| `bsp3_time_axis_weak` | `1.0` | 时间轴弱档阈值：`v > 该值` → `T1`（回抽急促）。同样要求 `0 < strong < weak` |

确认轴四档：`C3` 突破回抽笔端点 / `C2` 收复回抽幅度一半 / `C1` **跌回登记时锚定的中枢区间**（证伪终态，行保留不撤销）/ `C0` 窗口不足（盘中进行态）。

> **要素 E 为何不做成立判据**：E 需要未来 N 根笔才能判定，做成判据会使信号整体后移 1~2 笔（等于永远买在确认笔的高位，引入未来函数）。故三买照常在**回抽笔端点**输出，之后跌回中枢的标 `C1` 假三买供绩效分组，判定链本身零改动。

## 十三、配置指纹与重算影响

`WebAPI/config_fingerprint.py` 对配置求稳定哈希（16 位十六进制），落库时一并写入 `chan_snapshot.config_fingerprint`。`chan-config-panel` 起指纹改为**按模块分段**：

| 段 | 内容 | 说明 |
|---|---|---|
| `bsp` | `FINGERPRINT_KEYS` 的 37 项买卖点判据 | 原有能力；卖侧被 `-sell` 显式覆盖的项以 `key@sell` 追加 |
| `seg_bsp` | `macd_algo`、`bsp1_only_multibi_zs` | 线段级别的买卖点判据（独立于笔级别） |
| `bi` | `bi_algo`, `is_strict`, `bi_fx_check`, `gap_as_kl`, `bi_end_is_peak`, `bi_allow_sub_peak` | 笔算法 |
| `seg` | `seg_algo`, `left_method` | 线段算法 |
| `zs` | `need_combine`, `zs_combine_mode`, `one_bi_zs`, `zs_algo` | 中枢算法 |
| `macd` | `fast`, `slow`, `signal` | MACD 三参数（力度对比数值的基底） |
| `indicator` | `cal_rsi`, `rsi_cycle` | **仅当**笔级别 `macd_algo=rsi` 时才收录 |

另加常量 `LADDER_SCHEMA_VERSION = "bsp3-4axis-v1"`（阶梯口径版本号，每次口径变更都要 bump）。

`bsp` 段收录 36 个 key（`bs_type` 在构造期被消费成 `target_types`，不保留同名属性，实际入库 35 个）：

```
bsp_preset, divergence_rate, min_zs_cnt, bsp1_only_multibi_zs, max_bs2_rate,
macd_algo, bs1_peak, bs_type, bsp2_follow_1, bsp3_follow_1, bsp3_peak,
bsp2s_follow_2, max_bsp2s_lv, strict_bsp3, bsp3a_max_zs_cnt, bsp1_trend,
bsp1_new_extreme, bsp1_dif_div, bsp1_zero_axis, bsp1_trend_mode,
bsp1_new_extreme_mode, bsp1_zs_extend_to_seg_end, bsp2_retrace_zs,
bsp2s_require_zs, bsp2s_rate_mode, bsp3b_mode, bsp3_peak_on_breakout,
bsp3_follow_1_mode, bsp1_downgrade_to_pz, bsp1_force_scope, bsp1_qjt,
bsp1_qjt_depth, bsp3_confirm_window, bsp3_confirm_level,
bsp3_time_axis_strong, bsp3_time_axis_weak
```

**改动上述任一项都会使指纹变化 → `recompute_stock` 自动强制全量重算。** 这是刻意的：快照续算只重算未确认尾部，已确认前缀里的旧口径买卖点会原样保留，不做指纹校验就会出现新旧口径混在同一份 `bsp_index` 里的故障。

`chan-config-panel` 起，**结构与指标参数也已纳入指纹**（`bi`/`seg`/`zs`/`macd` 四段）——它们不是买卖点开关，但会改变买卖点赖以成立的结构：改 `bi_fx_check` 会重排所有笔，改 `zs_combine` 会改变中枢数量与边界，改 `macd.fast` 会改变力度对比数值。此前这三类改动只能靠人工记得「手动全量重刷」，现在由指纹兜住。

仍未纳入指纹的只有：运行模式（`trigger_step` / `skip_step`）、数据校验（`kl_data_check` 等）、以及纯看图指标（`cal_kdj` / `boll_n` / `mean_metrics` 等）——它们不改变买卖点成立性，纳入只会让无害改动触发昂贵的全量重算。

> **指纹结构变更是 BREAKING 的**：`bsp`/`seg_bsp`/结构段的引入使存量快照的指纹全部失配 → 升级后首次重算一律走全量（与 `LADDER_SCHEMA_VERSION` bump 同类机制，无需迁移脚本）。

## 十四、业务配置开放范围（配置抽屉）

`chan-config-panel` 起，缠论参数**已全部开放为业务配置**，通过 K 线页顶栏「缠论参数」按钮打开的配置抽屉维护。

### 14.1 开放范围

| 抽屉分组 | 项数 | 内容 |
|---|---|---|
| 买卖点判据 | 31 | 一买 / 二买 / 类二 / 三买 / T2·T3 阶梯 的成立性开关与阈值 |
| 证据阶梯标注 | 8 | 只改标注与排序，**不改成立性**（选中不会增减买卖点） |
| 高级 · 结构算法 | 15（+2 条件项） | 笔 / 线段 / 中枢 / MACD —— 改它会重排整张图，默认折叠并需二次确认 |

合计 57 项（31 + 8 + 15 + 3 条件项）。三个**条件项**按草稿值联动显示：`cal_rsi` / `rsi_cycle` 仅当 `macd_algo` 勾选了 `rsi` 时出现；`bsp3_follow_1_mode`（「一买类型」）仅当 `bsp3_follow_1`（三买必须跟在一买之后）开启时出现。因此默认档下抽屉实际显示 54 项；表格里的分组项数与抽屉标题显示的「N 项」都是**非条件项**口径（后端 `groups[].count` 不统计条件项）。每项旁有问号图标，悬浮显示白话解释（是什么 / 该控件怎么改会怎样 / 影响谁 / 出厂默认值）——说明卡第二段的标题跟随控件类型：数值类「调整数值」、单选「单选」、多选「多选」、开关「开关」。

### 14.2 三层优先级

配置的实际取值按下列顺序解析，后层覆盖前层：

```
① 内核硬编码默认（ChanConfig.py 的 para_dict）
        ↓ 被覆盖
② 档位预设展开（bsp_preset: standard / legacy）
        ↓ 被覆盖
③ 用户在抽屉里显式改过的项（PG chan_config.overrides）
```

档位名存在 `chan_config.preset` 列，**不在 `overrides` 里**——它不属于「用户改过的项」。因此计算出口（`chan_config_store.build_conf()` / `effective_config()`）必须把 `preset` 回填进传给内核的字典；漏了这一步，`CChanConfig` 只会看到硬编码默认 `standard`，**切到 legacy 后一处判据都不会跟着变**。同理，`GET /api/chan-config` 的 `effective` 与 `GET /schema` 的 `params[].default` 反射时也要补档位，否则界面显示的口径与图上真正算出来的不是一回事。

> 这个坑实测过：`preset=legacy` + 空 `overrides` 时，修复前 `min_zs_cnt` 仍是 2、`divergence_rate` 仍是 0.9、`bsp1_trend` 仍是 `True`（全是 standard 的值）。修复后正确变成 1 / `inf` / `False`。回归断言在 `Debug/test_chan_config_store.py` 第 7 组。

抽屉只把**与该档位预设基线不同的项**写进 `overrides`。这样内核将来调整默认值时，用户没改过的项会自动跟上，不会因一次保存就把旧默认固化下来。

**三条基线，语义完全不同，混用会出真实故障**（`GET /api/chan-config/schema` 同时返回）：

| 字段 | 含义 | 用途 |
|---|---|---|
| `params[].default` | 按**当前已保存配置**反射出的值 | 展示「这一项现在是多少」 |
| `kernel_defaults` | 内核出厂默认（`CChanConfig()` 空构造，等价 `standard` 档） | 只读参考 |
| `preset_baselines[档位]` | 该档位**预设展开后**的默认值 | **前端算 overrides 与「恢复默认」的唯一正确基线** |

两个已经踩过的坑：

- 用 `params[].default` 当基线 → **改动静默丢失**。用户改 A 项保存后，`default` 就等于 A 的新值；下次只改 B 项保存时，A 被判成「没改过」而踢出 `overrides`，A 的改动随之消失。
- 用 `kernel_defaults` 当基线 → **档位机制失效**。`legacy` 档会把 `divergence_rate` / `min_zs_cnt` / `bsp1_trend` / `macd_algo` 等十余项展开成不同取值，拿内核默认当基线会把这些**预设带来的**取值误判成用户覆盖写死进 `overrides`，此后切档位不再跟随预设。

### 14.3 生效方式

改动是**草稿态**：抽屉内所有编辑只改前端草稿，后端配置与图表都不动。点「保存并重算当前股票」才生效，且是两段式：

1. `PUT /api/chan-config` 落库并 bump `version`（失败 422 时抽屉保持打开、草稿不丢）
2. 前端按新配置重拉 `/api/klines`（秒级，用户立刻看到新图）
3. 后台 `POST /api/chan-config/recompute` 刷新该股票的 PG 索引（`bsp_index` / `chan_structure` / `chan_snapshot`），7~26 秒

参数是**全库共享**的全局设置。要让所有股票都跟上新口径，点抽屉内的「同步所有股票」——它等价于 `catch_up(force=True)`，逐键整套重写，进度写 `chan_config_sync_job` 表。

### 14.4 派生键

有 6 个取值会强制附带别的开关，由 `chan_config_store.apply_derived()` 在**计算出口**补齐（不改写用户存储的原值，也不出现在 `GET /api/chan-config` 的 `overrides` / `effective` 里 —— 那不是用户改过的项）：

| 触发条件 | 自动补的键 | 原因 |
|---|---|---|
| `macd_algo` ∈ {`volumn`, `amount`, `volumn_avg`, `amount_avg`, `turnrate_avg`} | `macd_algo-seg = peak`（用户已显式配过则保留用户值） | 量能类算法无法用于线段级别，`Seg.py` 会抛 `unsupport macd_algo` |
| `macd_algo = rsi` | `cal_rsi = True` | 不打开 RSI 指标计算，`klu.rsi` 属性不存在 |

抽屉里选中这些取值时，行下方会常驻显示回退说明（不只藏在问号里）——那是「你选的只半生效」的事实，必须一眼可见。

### 14.5 校验与降级

- **形态规整**：`"inf"` / `"-inf"` 字符串在保存前还原为 `float("inf")`。标准 JSON 不允许非有限浮点，前端勾选「不限（inf）」只能发字符串，不还原的话内核会把它当字符串存下，计算期 `"inf" <= 100` 直接 `TypeError`。`None` 一律拒绝（除了内核默认可空、语义为「不限制」的 `max_bsp2s_lv`）——前端旧版本曾把 `Infinity` 序列化成 `null`，内核构造能过但计算期 `None <= 100` 会崩。**读接口同理**：`GET /api/chan-config` 与 `GET /schema` 的整份响应都走 `encode_config()` 把 `inf` 转回 `"inf"`，否则 starlette 的 `json.dumps` 会抛 `Out of range float values are not JSON compliant` 直接 500（legacy 档 `divergence_rate=inf` 时必现）。
- **保存前构造期校验**：先用候选配置构造一次 `CChanConfig`，并显式调用 `parse_target_type()` 把 `bs_type` 的延迟断言前移。非法值返回 422，`detail` 含 `message` / `param` / `kernel_message` 三字段，前端据此定位到参数。校验失败**不写入任何内容**。
- **PG 不可达**：读接口降级为内核默认（`initialized=false`）不报错，`/api/klines` 与 `recompute_stock` 照常工作；写接口返回 503，拒绝静默成功。

### 14.6 回滚

把 `chan_service._make_chan_config()` / `incremental_engine._make_chan_config()` 改回硬编码
`CChanConfig({"trigger_step": ..., "kl_data_check": False})` 即可恢复改造前行为。此时因指纹失配会触发一次全量重算（快照口径回到硬编码默认），随后恢复增量。回滚**不清空** PG 里已保存的配置行——下次改回新实现时用户配置仍在。

### A.3 配置 key 与内部参数名不一致的三处

写配置字典时用**左列**的 key；读源码/调试时看到的是**右列**的属性名。这是 `CChanConfig` 的已知命名不一致，容易踩坑：

| 配置字典 key（对外） | 实际参数 / 属性名（内部） |
|---|---|
| `bi_strict` | `is_strict` |
| `left_seg_method` | `left_method` |
| `zs_combine` | `need_combine` |

其余所有参数两处同名。
