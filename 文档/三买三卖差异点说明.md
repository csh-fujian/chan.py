# 第三类买卖点（3a/3b）实现说明

> 对照对象：缠师原文的第三类买卖点定义 vs 本仓库 `ChanAnalyse/BuySellPoint/BSPointList.py` 中对 `T3A`/`T3B` 的拆分。
> 代码基线（2026-10-25，`chan-standard-bsp` 系列改造后）：`cal_seg_bs3point`（`BSPointList.py:878`）、`treat_bsp3_after`（`:931`）、`treat_bsp3_before`（`:997`）、`_treat_bsp3_before_legacy`（`:1070`）；判据函数在 `BSPJudgement.py`：`check_breakout`（`:262`）、`get_first_retrace`（`:285`）、`back_to_zs`（`:304`）、`check_zs_peak_on_breakout`（`:315`）。
> 阶梯（四轴）在 `WebAPI/bsp3_ladder.py` / `bsp3_confirm.py` / `bsp3_time_axis.py`。
>
> **统计口径**：文中「回抽是否回到中枢」的价格比对，以**判据链实际采纳的那个中枢**为基准（登记时快照进 `bsp3_zs_low` / `bsp3_zs_high` 两个只读 feature），而不是「回抽笔所在线段的最后一个中枢」。两者不等价，混用会得出错误结论。

---

## 一、理论定义

### 1.1 第三类买点 / 卖点

第三类买点：一个次级别走势**向上离开中枢**后，**次级别回抽**不再**回到中枢区间**（回抽低点高于中枢上沿 `ZG`）所形成的买点。
第三类卖点对称：向下离开中枢后，回抽高点低于中枢下沿 `ZD`。

判定要素：

| 编号 | 要素 | 严格内容 |
|---|---|---|
| A | 前提 | 必须先有一个**已成形的中枢** |
| B | 突破 | 存在离开该中枢的次级别走势，且**方向向外**（买：向上突破 `ZG`；卖：向下跌破 `ZD`） |
| C | 时序 | 突破之后的**第一次**次级别回抽（方向与突破相反） |
| D | 价格 | 回抽**不回到**中枢区间：买点回抽低点 `> ZG`；卖点回抽高点 `< ZD` |
| E | 后续 | 回抽结束后趋势延续（不跌回中枢） |
| F | 级别 | 回抽应为「次级别走势类型」，不是单笔 |
| G | 对称 | 买卖镜像同构 |

### 1.2 本仓库的两个变体

| 类型 | 代码锚点 | 含义 |
|---|---|---|
| `T3A` | `treat_bsp3_after` | 中枢位于**一买所在线段的下一条线段**内；取该线段**第一个**多笔中枢，回抽笔 = 离开笔 + 1 |
| `T3B` | `treat_bsp3_before` | 中枢位于**一买所在线段内**；取该线段**最后一个**多笔中枢，回抽笔 = 离开笔 + 1 |

「A/B」不是缠论原有概念，是仓库为区分「中枢在一买之后 / 之前」引入的编号（`文档/缠论策略.md:3.6`：「T3A 第三类买卖点(后)」「T3B 第三类买卖点(前)」）。**两者在标准档下判据同构**，差别只在锚定哪个中枢。

### 2.3 T3B：中枢在本线段

| 环节 | 代码位置 | 实际做了什么 |
|---|---|---|
| 取中枢 | `:1024` | `seg.get_final_multi_bi_zs()`：一买所在线段内**最后一个**多笔中枢 |
| 严格模式 | `:1029` | `strict_bsp3` 时要求中枢**离开笔** == 一买笔（与 T3A 是两种不同的「紧邻」定义，见 §3.3） |

| 回抽笔 | `:1045` → `get_first_retrace` | 离开笔之后的**第一笔**反向要素；若下一笔同向（离开未完成）则不成立 |

| 极值判据 | `:1057` | `bsp3_peak` 开启时判突破笔（与 T3A 同一语义） |
| 落库 | `:1068` | `add_bs(T3B, ...)` + 写 `bsp3_zs_low/high` 快照 |

### 2.4 公共判据

```python
# BSPJudgement.py:304  回到中枢区间 → 三买不成立
def back_to_zs(ele, zs) -> bool:
    return (ele.is_down() and ele._low() < zs.high) or \
           (ele.is_up()   and ele._high() > zs.low)

# BSPJudgement.py:315  突破笔是否冲破中枢内部极值（bsp3_peak 开启时）
def check_zs_peak_on_breakout(zs) -> bool:
    out = zs.bi_out
    if out is None:
        return False
    return out._high() >= zs.peak_high if out.is_up() else out._low() <= zs.peak_low
```

### 2.5 四轴阶梯（证据标注，不参与成立判定）

T3A/T3B 候选点在 `bsp_index.ladder` 落四轴组合值（`S|C|K|T`，无进度轴），全部为只读证据：

| 轴 | 前缀 | 档位 | 判据 |
|---|---|---|---|
| 佐证 | `S` | S3 / S2 / S1 | 回抽笔单笔窗口映射到子级别：子级已确认同向点 / 子级候选 / 子级末端分型 |
| 确认 | `C` | C3 / C2 / C1 / C0 | 事后窗口：C3 突破回抽笔端点、C2 收复回抽幅度一半、C1 跌回锚定中枢（证伪终态）、C0 窗口不足 |
| 分型 | `K` | K3 / K2 / K1 | 回抽笔末端分型的强弱（实体收复程度） |
| 时间 | `T` | T3 / T2 / T1 | 回抽速度比（回抽笔相对突破笔的振幅/时间），参照笔为**突破笔** |

无进度轴的原因：T3 判据链（A→B→C→D）在回抽笔端点一次性全部可判，成立即全链通过，不存在「推进到一半」的中间态（与 T2 的判据链不同）。已确认点为单值 `L4`。

## 三、最终结论

### 3.1 标准档：两分支判据同构，覆盖 A–D

`chan-standard-bsp` 改造后，`T3A` 与 `T3B` 都完整实现了理论要素 A–D：

| 要素 | 实现 |
|---|---|
| A 中枢前提 | 两分支都以多笔中枢为锚点（`get_first_multi_bi_zs` / `get_final_multi_bi_zs`） |
| B 突破方向 | 校验离开笔方向并确认真正越沿（`check_breakout`），买卖侧由离开笔方向决定 |
| C 第一次回抽 | 硬性取离开笔 + 1，方向必须相反；不满足即放弃 |
| D 不回中枢 | `back_to_zs` / `bsp3_back2zs`，触边归为「未回到中枢」 |

`T3A` 与 `T3B` 的差别只在锚定中枢的位置（下一线段 / 本线段），判据链本身相同。

### 3.2 要素 E：由确认轴承担，不进成立判据

**E 不做成成立条件**——E 需要未来 N 根笔才能判定，做成判据会使信号整体后移 1~2 笔，等于永远买在确认笔的高位（引入未来函数），且与缠论把 E 视作「持有期走势确认」的语义不符。

E 改由**事后确认层**落地：三买照常在回抽笔端点输出（进场点位不变），`WebAPI/bsp3_confirm.py` 在登记后的固定窗口内分档——C3 突破回抽笔端点 / C2 收复回抽幅度一半 / C1 跌回**登记时锚定的中枢区间**（证伪终态，行保留不撤销）/ C0 窗口不足（盘中进行态）。于是「之后跌回中枢的三买」被标为 C1 假三买，绩效统计可分组，而成立性判定完全不变。终态单向性由窗口封顶（窗口外数据不进输入）保证，重算结果恒定。

### 3.3 设计性收口（不再修复的三项）

| 项 | 结论 |
|---|---|
| `strict_bsp3` 双分支语义不同 | **结构性必然**：T3A 的中枢在下一条线段、T3B 的中心在本线段，「紧邻一买」不可能表达为同一条件。T3A 判「进入笔 == 一买笔+1」、T3B 判「离开笔 == 一买笔」，两分支条件不互换、不统一。默认 `False`，标准档输出不受影响 |
| 回抽是单笔而非次级别走势类型（要素 F） | **双口径**：线段级别输出承担严格语义（其要素为线段，天然具备内部结构），笔级别明确为单笔简化口径（`文档/缠论策略.md` 有映射说明）。把笔级别改成次级别判据等于推翻「笔为最小走势单元」的架构，代价与收益不成比例。线段级别的 T3 当前零下游消费，不新增暴露 |
| 3a/3b 编号非缠论原典词汇 | **保留**：标准档已消除 T3B 的宽松变体问题（同笔多类型重叠为空），剩余只是命名约定、无行为差异；改名破坏面覆盖 `BSP_TYPE` 枚举、`bs_type` 配置、PG 存量行、前端词表与十余个脚本，信号质量零提升。「A=中枢在一买之后 / B=之前」的语义在重写后依然成立 |

### 3.4 配置与回退

- `bsp3b_mode="standard"`（默认）/ `"legacy"`：只影响 T3B 判定，不影响 T3A
- `bsp_preset="legacy"`：一键回退全部六类买卖点到改造前口径
- `strict_bsp3` / `bsp3_peak` / `bsp3_peak_on_breakout` / `bsp3a_max_zs_cnt`：单项开关见 `Document/README.md`
- `bsp3_confirm_window` / `bsp3_confirm_level` / `bsp3_time_axis_strong` / `bsp3_time_axis_weak`：四轴阶梯参数（只影响证据标注），改动会触发配置指纹变化与全量重刷

### 3.5 实证现状与已知限制

- **标准档样本极稀**：41 只日线（QFQ，2019 起）只有 **1 个** T3 成立点（`sz.000027` 2023-12-15 三卖），其落盘阶梯为 `S1|C3|K3|T2`。样本量不足以给确认窗口、时间轴阈值定标——机制已就绪，结论待更大样本。
- **回刷已覆盖全部周期**：`Debug/bsp3_backfill_ladder.py` 按 DuckDB 实际存在的 (code, kl_type) 枚举键（日线/周线/月线/5m/15m/30m/60m），不再只跑日线。全周期回刷后库中 T3 行为 94 条：37 条 `L4`（3a）、43 条 `L4`（3b）、`S1|C3|K3|T2` 与 `C0|K2|T1` 各 1 条，其余 11 条 NULL 见下。
- **HFQ 无法重算**：`Data/kl_store.duckdb` 现存只有 QFQ 数据，索引中 HFQ 口径的 11 条 T3 行阶梯为 NULL，属既有数据状态而非本机制缺陷。补齐需先灌 HFQ 原始 K 线。
- **ST 标的**：`*ST` 在重算入口按 `exclude-st-stocks` D6 跳过，其存量行（`sz.000016` 日线一条旧 `L2`）不会被回刷覆盖。按该变更「存量 ST 数据保留」的要求**不删除**，但读侧（`bsp_store` 三个查询、策略引擎 `bsp_reader`、`monitor_store` 监控回查）已统一按 `ST_EXCLUDE_SQL` 过滤，因此不出现在任何页面与策略判定中。
- **佐证轴缺席是正常的**：佐证轴依赖子级别数据，只在带多级别装载的落库链路（`WebAPI` 重算）中出现。用单级别 `CChan` 复算同一标的会得到 `C3|K3|T2`——**阶梯组合串不以 `S` 开头同样合法**，比对时不可据此判定为旧语法。
