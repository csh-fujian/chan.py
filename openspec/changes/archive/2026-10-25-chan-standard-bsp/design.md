## Context

见 proposal.md 的 Why。本设计要解决的技术约束：

- **判定发生在计算内核中，且带增量游标**。`CBSPointList.cal` 由 `CKLine_List.cal_seg_and_zs` 调用，靠 `last_sure_pos` / `last_sure_seg_idx` 只重算未确认尾部。任何新增判据必须能在「只看到前缀 + 未确认尾部」的状态下工作，不能依赖全局后视统计。
- **两个层级共用一组函数**。`bs_point_lst`（笔级别）与 `seg_bs_point_lst`（线段级别）实例化的是同一个 `CBSPointList`，元素类型由泛型 `LINE_TYPE` 区分（`CBi` 或 `CSeg`）。
- **力度算法在两个层级不对等**。`CBi.cal_macd_metric` 支持 12 种；`CSeg.cal_macd_metric` 只支持 `slope` / `amp`（`Seg.py:202-212`），且 `ChanConfig.py:214-217` 把线段级别硬编码为 `macd_algo=slope`。
- **`CSeg` 能取到完整 K 线序列**（实测 41 只股票 300+ 线段，`seg.bi_list → bi.klc_lst → klu.macd` 的覆盖度 100%），因此补齐 MACD 算法没有数据障碍。
- **六类买卖点共用一条 `add_bs` 落库路径**（`BSPointList.py:219`）。`bsp_store_flat_dict` 按笔索引去重，`bsp1_dict` 只收 T1/T1P，`bsp_store_dict` 按类型分买卖两侧。任何口径改动都会同时影响笔级别与线段级别。
- **二买/三买都从 `seg.end_bi` 取一买锚点，且顺序固定**（`cal` 中 T1 → T2 → T3），因此 T2/T3 能读到 T1 的成立结果，反之不能。
- **下游三层耦合**：PG `bsp_index`（`WebAPI/bsp_store.py`、`incremental_engine.py`）、`WebAPI/bsp_ladder.py` 的 L3 预警、前端 K 线覆盖层。判定口径变化会传导到全部三层。

## Goals / Non-Goals

**Goals:**

- 把六类买卖点规范中的条件各自实现为**独立可开关**的判据，单项开关互相正交，便于逐条做一致性校验
- 一买判据抽成**与层级无关的纯函数**，笔级别与线段级别共用同一份实现
- 默认档位即为标准口径；`legacy` 档位能精确复现改造前输出（逐笔逐类型完全一致）
- 在不破坏增量游标语义的前提下引入新判据
- 二买 / 类二 / 三买B 的**语义修正与一买改造解耦**：各自有独立开关，可单独开启、单独回退、单独验证

**Non-Goals:**

- 不实现真正的跨级别区间套（用子级别数据递归定位）。`WebAPI/bsp_ladder.py` 现有的「子级别同向点 ±时间窗共振」近似保持原样
- 不改动笔、线段、中枢的构造算法（分型、特征序列、中枢合并）
- 不为二买/类二/三买引入独立的「次级别走势类型」实现（见 D19：线段级别承担该语义，笔级别保持单笔简化口径）
- 不引入买卖点的事后价格确认（差异点 4.9 / 二买 4.7）。该条需要「延迟确认 + 未来数据回填」机制，单列后续变更
- 不新增买卖点类型编号；`3b` 的语义被收紧但不改名（见 D18）

## Decisions

### D1：判据抽为层级无关的纯函数，两个层级复用

**做法**：新增模块内的纯函数 `_bsp1_standard_ok(ele, ele_list, zs_lst, cfg) -> (ok, reason)`，入参为「待判定要素 + 同层要素序列 + 同层中枢列表 + 配置」，不依赖 `bi_list` / `seg_list` 的类型。`treat_bsp1` 在笔级别调用它，线段级别路径也调用它。

**理由**：`CBSPointList` 已经是泛型的，`LINE_TYPE` 要么 `CBi` 要么 `CSeg`，两者都实现了 `is_down()` / `_low()` / `_high()` / `idx` / `get_begin_klu()` / `get_end_klu()`。唯一不通用的是 `cal_macd_metric` 支持面，靠 D2 补齐。

**备选**：为线段级别另写一套判据。否决——两份实现必然漂移，且规范要求买卖对称与两层级同构。

### D2：`CSeg` 补齐 MACD 系列算法，不再硬编码 slope

**做法**：把 `CBi` 的 `Cal_MACD_area` / `Cal_MACD_peak` / `Cal_MACD_half` / `Cal_MACD_diff` / `Cal_Rsi` 中「遍历笔的 K 线」逻辑抽成一个共享基类或模块级函数（入参为 K 线迭代器 + 方向 + 起止 idx），`CBi` 与 `CSeg` 各自调用。`CSeg.cal_macd_metric` 的分支从 2 项扩到与 `CBi` 一致。

**理由**：线段级别的 DIF 背驰与零轴回抽是 D2=A 路线的前提（见 proposal）。硬编码 `slope` 会让标准判据在线段级别根本无法表达。

**备选**：线段级别只做「结构判据」不做力度判据。否决——那样线段级别的「标准一买」缺一半定义。

**风险**：`CChanConfig` 现在强制 `seg_bs_point_conf.macd_algo="slope"`。改为默认 `peak`（与笔级别一致）后，`seg_bs_point_lst` 的既有输出会变。这属于预期的 BREAKING 范围。

### D3：新增 `diff_peak` 算法，保留 `DIFF` 不动

**做法**：`MACD_ALGO` 新增 `DIFF_PEAK`，语义为「笔区间内 DIF 线的极值」（买取 `min(DIF)`、卖取 `max(DIF)`）。现有 `DIFF` 实际算的是柱体 `max - min`，语义名不副实，但**保留不动**以免破坏既有配置。

**理由**：DIF 背驰判据需要的是「黄白线极值」，不是柱体差。新增而非修改，保证向后兼容。

**备选**：直接改写 `DIFF`。否决——`DIFF` 已出现在 `Document/README.md` 的参数表中，改写会让存量配置语义静默漂移。

### D4：零轴回抽用「区间内 DIF 是否出现反号」，不做「回抽过零再返回」

**做法**：取进入段结束 K 线到离开段开始 K 线之间的全部 K 线，检查 DIF 是否出现过与趋势相反的符号（买点出现 `DIF > 0`、卖点出现 `DIF < 0`）。

**理由**：缠师原文「b、c 两段均需回抽过零轴」在离散数据上最稳的可判定形式就是「两段之间曾穿越零轴」。若要求「穿越后再穿回」则退化为几乎不可判定（b 段结束与 c 段开始之间往往只有 1 根 K 线）。

**实测影响**：线段级 41 只日线，严格四条件（趋势 + 新低 + DIF + 零轴）后 T1 ≈ 5；去掉零轴 ≈ 16~23。该条件是最强的一道门，需在 tasks 中安排单独的一致性验证。

**备选**：用 MACD 柱是否过零。否决——用户已明确选择「黄白线（DIF）过零」口径。

### D5：趋势判据用「后一中枢上沿 < 前一中枢下沿」作为默认档

**做法**：买点要求 `z2.high < z1.low`；卖点要求 `z2.low > z1.high`。这是「两个中枢完全不重叠」的强趋势定义。

**理由**：这是缠师「依次下移」最无歧义的形式。较弱的定义（`z2.high < z1.high and z2.low < z1.low`）在实测中差异明显（41 只日线：强定义 47 个，弱定义 58 个），且弱定义会把「中枢扩张」误判为趋势。

**备选**：弱定义作为另一个档位选项。**保留**为 `bsp1_trend_mode="overlap"` 的备选值，默认 `strict`。

### D6：档位预设用「预设层 → 单项配置层」两层合并

**做法**：`CChanConfig` 中先应用 `bsp_preset` 展开的默认字典，再用用户显式传入的 key 覆盖。`legacy` 预设 = `{divergence_rate: inf, min_zs_cnt: 1, bsp1_trend: False, bsp1_new_extreme: False, bsp1_dif_div: False, bsp1_zero_axis: False, bsp2s_require_zs: False, bsp2s_rate_mode: "disp", bsp3b_mode: "legacy", bsp3_peak_on_breakout: False}`。

**理由**：`ConfigWithCheck` 已经是「消费 key 并对未知 key 抛异常」的严格校验器，两层合并天然契合它的现有结构。

**关键约束**：`legacy` 必须**逐笔逐类型**复现改造前输出，包括 `bsp1_list` 混入候选这一行为（差异点 4.7），以及二买/三买沿用旧配置方向、旧回撤量纲、旧后延扫描。这意味着「候选分层」与全部新开关都必须是预设的一部分，不能无条件生效。

**备选**：用环境变量或独立开关文件。否决——现有配置体系已有预设概念（`bs_type` 的逗号列表），沿用更一致。

### D7：候选分层用「新增成立集合」而非「改变候选集合」

**做法**：`bsp1_list` / `bsp1_dict` 保留现有语义（结构性候选，含未成立），另新增 `bsp1_sure_list` / `bsp1_sure_dict` 只收 `is_target_bsp=True` 的点。后续 `bsp2_follow_1` / `bsp3_follow_1` 的校验与 `relate_bsp1` 的取值都改用新集合。

**理由**：直接清空 `bsp1_list` 的候选会让 `bsp3_follow_1` 的「小转大」用法失效（README 明确该开关是为「一买因背驰不足没生成」的场景准备的）。新增集合既满足规范，又保留原有能力。

**备选**：直接把 `bsp1_list` 改为只收成立点。否决——破坏小转大场景。

### D8：放宽 4.8 采用开关，默认开启

**做法**：`treat_bsp1` 的进入条件中「中枢须延伸到线段末笔」部分改为受 `bsp1_zs_extend_to_seg_end` 控制，默认 `False`（即不再强制）。不满足该条件时**不再一律转 T1P**，而是仍走 `treat_bsp1`，由标准判据决定。

**理由**：实测该条把 114 个「中枢 + 突破 + 面积背驰」的合格候选挤进了 T1P，是纯实现的过滤而非理论要求。

**风险**：放宽后候选池从 134 增至 167，与趋势/新低判据的收紧方向相反。必须成对验证，避免净效果失控。

### D9：下游回刷走「整只股票整体替换」，不写增量迁移脚本

**做法**：判定口径变更后，调用 `WebAPI/incremental_engine.py` 现成的 `recompute_stock` 对全部已入库股票重跑一遍，`bsp_index` 按「整套替换」写入。

**理由**：`bsp-index` 规范已规定索引行按整套替换收敛（Scenario「修正后索引收敛」）。复用该机制无需新代码，也天然处理了 T1 行消失的场景。

**备选**：写 SQL 批量 `DELETE WHERE bsp_type='1'` 再靠后续补算填回。否决——会留下中间态空窗，且无法处理 T2/T3 因引用口径变化而产生的连带变化。

**补充（本变更扩展后）**：六类全都变化，T2/T2S/T3A/T3B 的行数与 `relate_bsp1` 指向同步变化，更强化了「整体替换而非按类型删除」的必要性。

### D10：「创趋势新低」的比较起点取「第一个中枢的进入段」

**做法**：以「用于认定趋势的两个中枢中，第一个中枢的进入要素」作为趋势起点，要求离开要素的极值严格优于该起点之后、到离开要素为止的全部同向要素。

**理由**：趋势 `a↓ → A → b↓ → B → c↓` 中，`a` 正是「进入第一个中枢的段」。以它为起点既覆盖完整趋势，又排除了趋势之前的历史数据。实测三种口径（41 只日线，笔级别候选 120）：

| 口径 | 笔级别通过 | 线段级别通过 | 问题 |
|---|---|---|---|
| 第一个中枢进入段 | 28 | 7 | — |
| 倒数第二个中枢进入段 | 63 | 8 | 只与 b 段比，不构成「趋势新低」 |
| 全部历史同向要素 | 26 | 4 | 趋势前的历史极值会永久封闭后续信号 |

**备选**：`bsp1_new_extreme_mode` 保留后两种作为可选值，默认取 `trend_start`。

### D11：快照与缓存增加配置指纹，不匹配即失效

**做法**：`chan_snapshot` 与 `chan_stable_prefix` 两张表各增一列 `config_fingerprint`（对买卖点相关配置求稳定哈希）。快照用于续算前比对，不一致则强制 `force_full=True`；缓存 `get` 时比对，不一致即视为未命中。

**理由**：两张表的键分别是 `(code, kl_type, autype)` 与 `(code, kl_type)`，**都不含配置**。切档位后：

- 缓存命中会直接返回旧 JSON，连计算都不发生；
- 快照续算只重算未确认尾部，已确认前缀里的旧 T1 原样保留，导致新旧口径的买卖点混在同一份 `bsp_index` 里。

「配置改了但输出没变」是最难排查的故障形态，必须在数据层堵死。

**备选**：切档位时手工清空两张表。否决——依赖人工纪律，且未来任何新增配置项都会重演。

### D12：指纹失效的代价是「切档位时首轮全量重算」

**说明**：D11 的副作用需要明确记录——**切档位后每只股票的第一次重算会退化为全量计算**（`incremental_engine.py` 的 `mode` 从 `incremental` 变 `full`），第二次起恢复增量。

**影响量化**：以 41 只日线为参照，全量重算单只约 0.3~1.2 秒（含段/中枢/买卖点全链路），全库首轮回刷是**一次性成本**，与 D9 的迁移回刷本来就要做的那一轮重合，不产生额外轮次。

**这是正确行为而非性能缺陷**：没有指纹就必须全量重算才能保证结果属于新档位；保留增量反而会得到新旧口径混杂的错误输出。**不得为了省这一轮而跳过指纹校验。**

**运维约定**：`bsp_preset` 或任一新增开关发生变更后，应主动执行一次全库 `recompute_stock(force_full=True)`，把首轮全量代价从「用户请求时被动触发」变为「运维窗口内主动完成」。

### D13：二买的 `relate_bsp1` 与 `follow` 校验统一到成立集合

**做法**：`treat_bsp2` 中 `real_bsp1 = self.bsp1_dict.get(bsp1_bi.idx)` 改为 `self.bsp1_sure_dict.get(bsp1_bi.idx)`；`bsp2_follow_1` 的校验从 `bsp_store_flat_dict` 改为 `bsp1_sure_dict`（与 D7 一致）。另在 `treat_bsp3_before/after` 中同样处理 `relate_bsp1`。

**理由**：当前是**双口径**——`relate_bsp1` 取候选（`bsp1_dict` 含未成立点）、`follow` 校验取全类型已登记（`bsp_store_flat_dict`）。实测默认阈值下两者「恰好」一致（47/47 命中），但这是 `bsp1_bi = seg.end_bi` 与落库笔相同的巧合；一旦 `bsp2_follow_1=False`，2 买从 18/29 暴增到 71/71，其中 **22 个 `relate_bsp1` 指向未成立的一类候选**。下游若用 `relate_bsp1` 做「二买必有一买」的展示或风控，会引用到未成立的点。

**备选**：保留双口径并在文档中说明。否决——规范明确要求「后续二类、三类买卖点引用一买锚点时使用成立口径」，双口径就是规范要消灭的形态。

### D14：修正 `treat_bsp2` 首线段分支的配置方向

**做法**：`else` 分支的 `BSP_CONF = self.config.GetBSConfig(seg.is_up())` 改为 `seg.is_down()`，与 `len(seg_list) > 1` 分支及同函数内的 `treat_bsp2s`（`:429`）一致。

**理由**：其余所有分支都按 `seg.is_down()` 选配置（下线段 → 买侧配置）。首线段用 `seg.is_up()` 使买卖两侧的配置完全颠倒——一旦用户用 `-buy` / `-sell` 后缀分别配置参数，首线段会取错。实测当前 41 只日线中**只有 1 条线段的标的数为 0**，所以此错误在现有数据上未暴露；但它是确定性的语义错误，不是数据问题。

**备选**：保留现状并加注释说明「首线段的方向语义特殊」。否决——同函数内 `treat_bsp2s` 已用相反方向，自相矛盾无法自圆其说。

**风险**：修正后若标的只有一条线段，其 T2/T2S 会用另一侧配置重算。现有数据集上无样本，风险为零；但需在 tasks 中构造合成数据验证。

### D15：类二补中枢前提，用「末端价格落在中枢区间内」而非「区间有交集」

**做法**：新增 `bsp2s_require_zs`（默认 `True`）。在 `treat_bsp2s` 每登记一个 T2S 前，要求 `bsp2s_bi.get_end_val()` 落在 `seg.zs_lst` 中某个非单笔中枢的 `[low, high]` 内；`seg` 取 `bsp2s_bi.parent_seg`。线段内无多笔中枢时直接不产出。

**理由**：类二的理论定义是「中枢内的多次回抽」，中枢是定义性前提。代码中 `treat_bsp2s` **完全不引用任何中枢对象**——对照三买的 `treat_bsp3_after/before` 都显式取 `zs`、一类显式取 `seg.zs_lst[-1]`，只有二买与类二没有中枢概念。

实测三种候选口径（157 个 T2S）：

| 口径 | 存活 | 说明 |
|---|---|---|
| 末端价格在中枢 `[low, high]` 内 | 90 | 最严，真正「在中枢内」 |
| 末端价格不低于中枢下沿（买）/ 不高于上沿（卖） | 57 / 33 | 较弱，允许在中枢外部一侧 |
| 整笔区间与中枢有交集 | 151 | 最松，几乎不过滤 |
| 所在线段无多笔中枢 | 6 | 无论哪种口径都应剔除 |

选最严口径：它与「中枢内回抽」的字面语义一致，且保留 90 个（仍多于二买的 166 → 按 `min_zs_cnt=2` 档为 29）。用「有交集」口径只剔除 6 个，等于没加约束。

**备选**：用「区间有交集」。否决——实测 151/157 通过，过滤力接近零，无法支撑「中枢是前提」的主张。

**风险**：默认开启会让 T2S 从 157 降到 90（约 -43%）。这是预期的口径收紧，已纳入 BREAKING 范围。

### D16：类二回撤率统一为 amp 量纲，旧量纲保留为档位

**做法**：新增 `bsp2s_rate_mode`，默认 `"amp"`：`retrace_rate = bsp2s_bi.amp() / break_bi.amp()`（与二买同构）。旧口径 `"disp"`：`abs(bsp2s_bi.get_end_val() - break_bi.get_end_val()) / break_bi.amp()`。

**理由**：两个公式共用同一个 `max_bs2_rate` 阈值但量纲不同（二买比「两笔振幅」，类二比「端点位移与振幅」），同一个阈值在两类点上含义不等价。实测两口径差值：16 个 ≤0.05、58 个 >0.05、83 个 >0.2——多数样本显著不同。改用 amp 后 `max_bs2_rate=1.0` 时 T2S 从 157 降到 144、0.618 时从 83 降到 66。

**备选**：为类二单开阈值 `max_bsp2s_rate`。否决——增加一个需要独立调参的旋钮，而问题本质是「同名言不同义」，统一量纲更根本。

### D17：修正 `bsp2s_follow_2` 的语义位置

**做法**：把 `elif BSP_CONF.bsp2s_follow_2: return` 从「二买未命中」分支移到 `treat_bsp2s` 的入口判断，语义改为「`bsp2s_follow_2` 为真且锚点二买未成立 → 直接返回」。

**理由**：文档（`Document/README.md:543`）写的是「类2买卖点是否必须跟在2类买卖点后面」，代码却在「二买成立」时完全无视该开关。逻辑推论：当前开关的真实语义是「**二买失败时是否放弃类二**」，与文档**相反**。在默认 `max_bs2_rate=1.0` 下二买几乎全成立（167 个），所以开关实测完全无效（157 → 157）；一旦阈值收紧到 0.618，修正后 T2S 从 83 降到 60，开关才真正生效。

**关键点**：这不是「开关坏了」，而是「开关只在二买失败率高的配置下才可观察」。当前默认阈值把它的作用域压成了空集。修正后语义与文档一致，且在默认档位下仍表现为「无差异」（因为二买几乎全成立）——这正是正确的行为，不是失效。

**备选**：保留现状，只改文档描述。否决——文档描述的是符合缠论直觉的语义，改文档等于固化一个反直觉的行为。

**另一个实测量**：按 `bsp2s_lv` 回溯锚点二买笔，默认档 157 个 T2S 中孤儿 0 个、legacy 档 317 个中孤儿 1 个。这说明**在当前数据上，锚点二买几乎总能成立**——所以 D17 的实际影响主要在「收窄阈值后的配置」而非默认档。这一点必须写进文档，避免用户误以为开关无效。

### D18：T3B 重定义为标准三买，旧行为保留为 `bsp3b_mode="legacy"`

**做法**：

- 锚点：`seg.get_final_multi_bi_zs()`（不变，仍是「一买所在线段内最后一个多笔中枢」）
- 突破校验（新增）：买要求 `bi_out.is_up() and bi_out._high() > zs.high`；卖要求 `bi_out.is_down() and bi_out._low() < zs.low`
- 回抽笔：`bi_list[bi_out.idx + 1]`（不再从 `bsp1_bi.idx + 2` 起每隔 2 笔扫描）
- 回抽方向（新增）：买要求 `is_down()`、卖要求 `is_up()`
- 遇回中枢：`break`（不再是 `continue`，即不后延）
- 旧行为整体保留为 `bsp3b_mode="legacy"`

**理由**：当前 T3B 的 11 个样本中，回抽笔与中枢离开笔的间隔分布是 2 笔 6 个、4 笔 3 个、10 笔 1 个、14 笔 1 个，**0 个是「第一次回抽」**；7/11 与 T2/T2S 落在同一笔；3/11 在突破笔之后已有同向笔重新进入中枢（中枢支撑已被证伪）。它不是三买，而是「价格位于中枢之上（下）的同向回踩」的机械筛选。

**重要实测纠正**：先前用 `zs.bi_out` 直接做「突破方向校验 + `bi_out.idx+1`」的写法会让 T3B 归零，原因是误以为 `bi_out` 是「向上突破笔」。实际 `bi_out` 是**中枢的离开笔**，其方向与趋势延续方向一致（买点场景下是向下笔）。正确做法是：以 `bi_out` 为离开笔、按买/卖方向要求其方向与突破方向一致，此时 `bi_out.idx+1` 才是反方向的第一笔回抽。

修正后实测（41 只日线，笔级别）：

| 约束 | 买 | 卖 | 合计 |
|---|---|---|---|
| 离开笔突破 + 下一笔反抽不回中枢 | 75 | 71 | 146 |
| 再要求回抽笔在一买笔之后 | 45 | 36 | 81 |
| 当前 `bsp3b_mode="legacy"` 输出 | — | — | 33 |

标准化后数量**增加**（33 → 81），因为「每个中枢一条」比「每个线段只取第一个」覆盖更广。同时与其他类型重叠从 7/11 降到 0（`overlap_T2=0`、`overlap_T2S=0`），仅 15 个与 T3A 重叠。这是正确的：标准三买本来就可以与三买A 在不同中枢上并存。

**备选**：把 T3B 直接废弃、只保留 T3A。否决——T3B 覆盖的是「中枢在同一线段内」的情形，T3A 覆盖「中枢在下一条线段内」，两者互补，废弃会丢失一半形态。

### D19：`bsp3_peak` 的判据对象改为「突破笔」，且两条分支都生效

**做法**：把 `bsp3_break_zspeak(bsp3_bi, zs)` 的入参从回抽笔改为中枢的离开笔 `zs.bi_out`；在 `treat_bsp3_before` 中也调用该判据。新增 `bsp3_peak_on_breakout` 配置项控制新语义，默认 `True`；设为 `False` 时恢复旧语义（判回抽笔）且只在 T3A 生效。

**理由**：README `:545` 写的是「3类买卖点**突破笔**是不是必须突破中枢里面最高/最低的」，代码传入的却是回抽笔 `bsp3_bi`。语义被偷换成了「回抽笔本身是否冲破中枢极值」——对买点尤其别扭（下降回抽笔的高点要高于中枢内所有笔的高点）。且 `treat_bsp3_before` 完全不调用该判据，实测 `bsp3_peak=True` 时 T3A 从 9 降到 8、T3B 保持 11 不变，开关成了「3a 专属」。

**风险**：判据对象变更会让 T3A 的极值过滤结果变化（实测旧语义下过滤掉 1 个）。需在 tasks 中单独测量新旧语义的差异样本。

### D20：`bsp3_follow_1` 改用一买专用集合

**做法**：`cal_seg_bs3point` 的校验从 `bsp_store_flat_dict` 改为 `bsp1_sure_dict`（成立口径）或 `bsp1_dict`（候选口径，由 `bsp3_follow_1_mode` 控制，默认 `sure`）。

**理由**：`bsp_store_flat_dict` 由 `store_add_bsp` 写入，**所有类型**都会登记。计算顺序是 T1 → T2 → T3，到三买时 flat dict 里已混入二买/类二。某笔若只是二买、并非一买，也能让 `bsp3_follow_1` 通过。实测当前 20 个三买的 `relate_bsp1` 类型分布为 T1:17 / T1P:3（全部非空），说明**现有数据尚未暴露该问题**，但校验口径与 `relate_bsp1` 的取值口径不一致是确定的缺陷。

**备选**：在 `bsp_store_flat_dict` 里按类型过滤。否决——多一层查表且语义不如「专用集合」直白。

### D21：二买「回调须与中枢关联」作为可选开关，默认关闭

**做法**：新增 `bsp2_retrace_zs`（默认 `False`）。开启后要求回调笔 `bsp2_bi` 的高低区间与一买所在线段的某个多笔中枢有交集，否则不产出二买。

**理由**：理论上二买的回调是「次级别走势类型」，应落在中枢区间内。但**二买的骨架本身是正确的**（`+1/+2` 时序、「不破一买」由 `max_bs2_rate <= 1` 数学保证），强行默认开启会改变一个已被验证正确的类型。实测 15 个二买的回调笔「等于所在线段末笔的比例为 0」，说明回调笔总在线段内部——这是笔级别地址化的自然结果，不是缺陷。

因此把它做成**可选开关**：想让二买带上中枢语义的用户可以开；需要与旧结果对齐的场景保持关闭。这与 D18（T3B 重定义）、D15（类二补中枢）的处理不同——那两类是**当前完全不满足理论定义**，必须默认修正；二买是**骨架正确、仅少一层结构注释**，不应强改。

**备选**：默认开启。否决——会让一个正确实现的类型凭空收紧，且与「不破坏已验证正确部分」的原则冲突。

### D22：三买A/B 的重叠不视为缺陷，用 `primary_type` 供下游去重

**做法**：`CBS_Point` 增加只读属性 `primary_type`（按固定优先序 `T1 > T1P > T2 > T3A > T3B > T2S` 取 `type` 列表中的第一个），`bsp_type` 落库时用它；`type` 列表本身不变。同时保留 `type` 的全集供需要「一个位置多信号」的下游使用。

**理由**：标准化后 T3B 与 T3A 有 15 个重叠（不同中枢上的三买可以同时成立，这在理论上是允许的），与 T2/T2S 的重叠降为 0。下游 `bsp_index` 若按类型分行写入，同一笔会产生多行，绩效统计的分母被放大。`primary_type` 提供一个确定性的去重键，且不破坏 `type` 的既有语义。

**备选**：在 `bsp_index` 写入时按 `bi.idx` 做 `GROUP BY` 取 MIN(bsp_type)。否决——把口径判断推到 SQL 层，前端与 CLI 路径仍会重复计数；放在 `CBS_Point` 上三处受益。

### D23：二买/类二/三买的新判据复用一买的「要素无关」抽象

**做法**：D1 的纯函数只处理一买。二买/类二/三买的中枢校验也抽为模块级函数（`_retrace_in_zs(ele, zs_lst)`、`_breakout_ok(out_bi, zs, is_buy)`、`_first_retrace(el_list, out_bi)`），同样不依赖 `CBi` / `CSeg` 的具体类型。

**理由**：`seg_bs_point_lst` 与 `bs_point_lst` 共用 `CBSPointList`。若只为笔级别写判据，线段级别的二买/三买会沿用旧逻辑，导致两个层级的「标准口径」不一致。实测线段级别当前输出极少（12 只样本中 T1 合计 4、T2 合计 3、T2S 合计 1、T3A/T3B 各 1），改造后仍会很少，但**一致性比数量重要**。

**备选**：只改笔级别。否决——`CChan[KL_TYPE].seg_bs_point_lst` 是公开 API，两个层级口径分叉会在绘图与下游产生难以解释的差异。

## Risks / Trade-offs

- **T1 数量下降一个数量级以上（258 → 5~23 / 41 只）** → 下游 `bsp_index`、监控预警、策略任务会近乎静默。缓解：`bsp_preset="legacy"` 可一键回退；上线前在 `regression-testing-change` 中固化前后对照基线；对前端空态文案做同步。
- **类二数量下降约 43%（157 → 90 / 41 只）** → 类二原本是数量最多的一类，下降后「高频信号」特征减弱。缓解：`bsp2s_require_zs=False` 可恢复；文档明确说明这是口径收紧而非信号消失。
- **T3B 数量增加（33 → 81）且与 T3A 有 15 个重叠** → 下游若按类型分行统计会放大三买总数。缓解：D22 的 `primary_type` 提供去重键；`bsp-index` 规范新增「按笔去重」Scenario。
- **`legacy` 预设与默认档位必须逐笔完全一致** → 若漂移，回退能力就是假的。缓解：新增等价性脚本，对 41 只日线逐笔逐类型比对（参照 `Debug/bsp_engine_regression.py` 的既有模式）。
- **线段级别 MACD 算法改动会改变 `seg_bs_point_lst` 全部输出** → 前端绘图与 `bsp_ladder` 的 L1 共振都可能偏移。缓解：把该改动与一买判据改动分阶段提交，各自独立验证。
- **放宽 4.8 与收紧判据方向相反** → 净效果可能不符合预期。缓解：在 tasks 中要求「逐条开关单独测量 + 组合测量」两张表。
- **新增判据都依赖全局同向要素序列** → 在增量模式下，`bi_list` 的尾部可能只有虚拟笔。缓解：判据只使用「`idx <= 当前元素 idx` 且 `is_sure=True`」的要素；对未确认尾部按现有 `clear_store_end` 机制随重算收敛。
- **`bsp2s_follow_2` 修正后默认档仍表现为「无差异」** → 用户可能误以为开关没修好。缓解：文档明确写出「该开关只在二买失败率高的阈值下可观察」，并在 tasks 中固化 0.618 / 0.5 两组对照数字。
- **`CChanConfig` 未知 key 严格校验** → 新增配置项若在调用方拼错会直接抛异常。缓解：在 `_ensure` 之外补一个 `bsp_preset` / `bsp3b_mode` / `bsp2s_rate_mode` 的取值白名单校验。
- **切档位首轮退化为全量重算（D12）** → 全库首轮耗时上升，且该退化在用户请求时被动触发会表现为「某只股票响应变慢」。缓解：变更档位后主动跑一次全库 `recompute_stock(force_full=True)`，把代价收敛到运维窗口内；不得为规避它而跳过指纹校验。

## Migration Plan

1. **阶段 0（无破坏）**：新增配置项与预设解析、新增 `diff_peak` 枚举与算法、`CSeg` 补 MACD 算法、新增 `primary_type`。此时默认档位仍为 `legacy` 语义等价物，输出不变。
2. **阶段 1（默认切换）**：把默认档位切到标准口径，同时提供 `bsp_preset="legacy"`；同批上线 D11 的配置指纹列（幂等 DDL）。此步是 BREAKING 点，且首次全库重算会因指纹不匹配全部退化为全量（D12）。
3. **阶段 2（下游回刷）**：对 PG 中全部已入库股票执行 `recompute_stock(force_full=True)`，`bsp_index` 整套替换。主动执行以把 D12 的全量代价收敛到运维窗口内。
4. **阶段 3（文档同步）**：`文档/缠论策略.md`、`Document/README.md`、三份《xx买xx卖差异点说明》回标。
5. **回滚**：把默认 `bsp_preset` 设回 `legacy`，再执行一次阶段 2 的回刷即可（同样会因指纹变化触发一轮全量重算）。单项开关也可单独回退（如仅 `bsp3b_mode="legacy"`）。

## Open Questions

- 线段级别的「标准一买」是否需要单独暴露给前端（当前前端只消费 `bs_point_lst`）？可在实现完成后按页面需要再定，不影响判据本身。
- `primary_type` 的优先序（`T1 > T1P > T2 > T3A > T3B > T2S`）是否需要在业务侧可配？当前按「信号强度」固定，若业务更看重「时效性」则 T2 应排在 T3A 之前。可在落库侧先观察，不影响内核。
