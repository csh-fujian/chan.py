# Design

## Context

见 proposal.md - Why（极值严格性）。本设计文档同时承载 2026-10-25 至 2026-10-26 轮次排查得出的
**一买判据失效链**结论，该结论把本变更从「极值口径收紧」扩展为「一买候选判定的区段化重构」，
因为它暴露了比相等极值更硬的三个前置卡点。

### 排查基准案例

`sz.000001`（平安银行）日线，2026-07-01 低点 **9.7747**，人工认定为一买。当前代码在全部
`begin_time` 取值下均判不出一买（`bs_point_lst.bsp1_sure_list` 为空）。

### 三层卡点（按硬性程度排序）

```
第 1 关  线段归属     候选笔不是任何线段的终点笔        最硬的墙
第 2 关  线段内中枢数  seg.zs_lst 只有 1 个（需 >= 2）   线段边界切碎中枢
第 3 关  力度口径      PEAK 判不出，FULL_AREA 能判出     本变更主体
```

**第 1 关**：`cal_seg_bs1point` 只遍历 `seg_list[last_sure_seg_idx:]`，且买卖点只能挂在
`seg.end_bi` 上。实测 `begin=2018-01-01` 时候选为 bi109，而线段终点笔集合是
`[0,5,22,25,38,53,58,63,66,77,82,87,96,103,112,113]` —— bi109 不在其中。

**第 2 关**：实测四个 `begin_time` 起点（2018/2019/2023/2025-06）结果完全一致：

```
所属 seg = UP 线段（含 bi109/bi97/bi43/bi13）
seg.zs_lst 数 = 1    多笔中枢数 = 1
[10.1074, 10.5527]  bi105-bi109（2018 起点）
```

`min_zs_cnt=2` 直接返回 False，力度判据根本走不到。另一组中枢 `[10.7042, 11.0926]`
落在前一个线段内，被线段边界切断 —— 这正是 proposal.md 引用的 §4.1 实证
「55/66 的 T1 位置上全级别多笔中枢数多于线段内中枢数」的具体成因。

**第 3 关**：在正确的观察区段（bi97~bi108 构成 2 中枢）下，逐项跑六条判据：

| 判据 | 结果 | 实测 |
|---|---|---|
| ① 趋势前提（strict） | PASS | `z2.high=10.5527 < z1.low=10.7042` |
| ② 突破中枢 | PASS | `9.7747 < 10.1074` |
| ③ 创趋势新低 | PASS | 无更低的下跌笔 |
| ④ DIF 背驰 | PASS | `out=-0.1259 > in=-0.1527` |
| ⑤ 零轴回抽 | PASS | 期间 DIF>0 出现过 |
| ⑥ **力度背驰** | **FAIL** | `c/b = 1.7880 > 0.9`（PEAK 口径） |

同一组 b/c 段，只换力度算法：

| MACD_ALGO | b | c | c/b | 背驰 |
|---|---|---|---|---|
| **PEAK**（standard 档当前默认） | 0.0895 | 0.1599 | **1.7880** | 否 |
| AREA | 0.1106 | 0.7314 | 6.6107 | 否 |
| **FULL_AREA** | **0.9136** | **0.7314** | **0.8005** | **是** |
| DIFF | 0.1137 | 0.3112 | 2.7362 | 否 |
| SLOPE | 0.0030 | 0.0086 | 2.8387 | 否 |
| AMP | 0.0850 | 0.1120 | 1.3180 | 否 |

成因：c 段（bi109）13 个交易日跌 11.2%，b 段（bi103）27 个交易日跌 8.5%。c 段跌幅更大、
时间更短 → 单根 MACD 柱峰值更深（PEAK 判不背驰），但整段 MACD 面积更小
（FULL_AREA 判背驰）。这是缠论最典型的面积背驰形态，也是急跌赶底一买的常见形态。

### 已排除的假设（避免后续重复排查）

- **`ele_inside_is_sure` 冻结机制不是卡点**。实测四种冻结策略（原版 / 尾部 3 段可重算 /
  尾部 5 段可重算 / 完全不冻结）结果完全一致：`bsp=4, bsp1候选=14`，耗时 0.21~0.26s。
  该机制是性能优化，不是行为限制。
- **笔层识别正确**。bi109 DOWN 从 06/12 顶分型（klc1542，H11.0075）走到 07/01 底分型
  （klc1552），顶分型确实存在，包含关系处理正确。卡点在线段层及以上。
- **`check_dif_divergence` 口径无需修改**。在该点上 DIF 判据 PASS，`bi_in` 结构正确、
  全历史 13/13 同向。此前怀疑的「上涨中枢 bi_in 与下跌笔比」不成立。

## Goals / Non-Goals

**Goals:**

- 把「力度口径从 PEAK 改为 FULL_AREA」作为独立、可单独验证的改动落地（41 只样本已横评）。
- 记录并锁定「观察区段」的起点规则 —— 这是第 2 关的解法，且实测两种候选规则结论相反。
- 记录「区段中枢构建器的区间演化策略」—— `shrink` 是唯一在全部起点下稳定的策略。
- 为第 1 关（线段归属）留出明确的后续变更边界，不在本变更内解决。

**Non-Goals:**

- **不在本变更内实现观察区段或区段中枢构建器**。它们影响 `CZSList` / `update_zs_in_seg`
  的架构，需要独立的 spec 与回归基线，本变更只固化设计与实测结论。
- 不修改 `check_dif_divergence`（已验证无需修改）。
- 不修改虚段触发链路（`treat_pz_bsp1` 的 `seg_idx` 早退检查）—— 属于第 1 关。
- 不引入区间套（`bsp1_qjt`）相关改动。

## Decisions

### D0: 极值严格性必须做成档位开关 `bs1_peak_strict`

**决定**：新增配置项 `bs1_peak_strict`，`standard` 档默认 `True`（严格优），
`_BSP_PRESETS["legacy"]` 显式写 `False`（宽松，相等极值放行）。

**为什么不能「无开关地全局收紧」**（原方案，实施时被实测否决）：

`bs1_peak` 在 legacy 档是**开启**的——`_BSP_PRESETS["legacy"]` 只关了四项标准判据
（`bsp1_trend` / `bsp1_new_extreme` / `bsp1_dif_div` / `bsp1_zero_axis`），从未关 `bs1_peak`。
因此 `out_bi_is_peak` 一旦全局收紧，legacy 档立刻偏离基线：

| 档位/级别 | 无开关（全局严格优） | 基线 | 差异点 |
|---|---|---|---|
| legacy 笔级 | 255 / 69 / 315 / 314 / 59 / 50 | 258 / 69 / 318 / 317 / 61 / 50 | −3 / 0 / −3 / −3 / −2 / 0 |
| legacy 线级 | 37 / 8 / 35 / 15 / 2 / 6 | 同左 | 无（线段级 `bsp1_only_multibi_zs=False`，affected 点不在线段级候选内） |

三个差异点均为**浮点精确相等**的极值：

| 代码 | 日期 | 离开笔 | 中枢内冲突笔 | 形态 |
|---|---|---|---|---|
| sh.600006 | 2025-08-25 | bi77 UP high=8.9400 | bi74 DOWN high=8.9400 | 双顶 |
| sh.600026 | 2021-02-05 | bi25 DOWN low=5.2802 | bi21 DOWN low=5.2802 | 双底 |
| sz.000007 | 2023-11-03 | bi55 UP high=5.3500 | bi53 UP high=5.3500 | 双顶 |

判据层面严格优是对的（这三例正是「回到前高/前低」，不应算创出）；问题在于
proposal 同时保留了「legacy 逐笔等价」这条硬契约，两者不可兼得。加开关是唯一
能同时满足两者的方式，也与 `_BSP_PRESETS["legacy"]` 已有的防御性显式写法
（`bsp1_force_scope="bi"`、`bsp1_qjt=False`）一致。

**验证**：`Debug/bsp1_extreme_strict_synth.py` 对同一桩件用例断言
`strict=True → False` / `strict=False → True`；完整回归第 1 节两侧 `✓ 完全一致`。

**连带后果**：standard 档 T1P 由 53（bi）/52（swing）降为 50/49 —— 三个点原本
走降级路由落 T1P（`single_zs` 成因），严格优后 `peak_ok=False`，降级条件
（`peak_ok` 是必要条件之一）不再满足，点被丢弃。降级漏斗第 4/5 档由
142/53 变为 139/50。

**这三例的严格性来自 `check_new_extreme`（1.1），不是 `bs1_peak_strict`（1.2）**
——实施后实测澄清的归因，原稿写混了：

| 代码 | 离开笔 | `bs1_peak_strict=False` 下 | `bsp1_new_extreme=False` 下 | 实际卡点 |
|---|---|---|---|---|
| sh.600006 | bi77 UP high=8.9400 | 仍消失 | 出现（T1P，`single_zs`） | `check_new_extreme` 严格优 |
| sh.600026 | bi25 DOWN low=5.2802 | 仍消失 | 出现（T1P，`single_zs`） | `check_new_extreme` 严格优 |
| sz.000007 | bi55 UP high=5.3500 | 仍消失 | 出现（T1P，`single_zs`） | `check_new_extreme` 严格优 |

原因是降级路由的重跑副本会把 `bsp1_new_extreme_mode` 强制改为 `"all"`（D1-c），
但**不会**改变 `check_new_extreme` 的比较严格性——严格优是 1.1 的代码级改动，
没有开关；`bsp1_new_extreme` 这个开关只控制整条判据是否参与。所以这三个点在
standard 档是被「新低比较」拦下，与 `bs1_peak_strict` 无关。

`bs1_peak_strict` 真正覆盖的是 **legacy 档的 `out_bi_is_peak`**：那里没有降级路由、
没有新低判据，宽松/严格之差直接改变成立性（D0 上半部分的 258→255 三个点）。
两条判据的严格性必须同源（1.2 的 docstring 已写明这一契约），但它们被
哪个开关影响、影响哪条路径，是两回事。

### D1: 力度算法默认值 `peak` → `full_area`

**决定**：`ChanConfig.py` 中 `macd_algo` 默认值改为 `"full_area"`，`_BSP_PRESETS["legacy"]`
显式写入 `"macd_algo": "peak"` 锁死等价基线。

**理由**：41 只日线横评（2019-01-01 起，QFQ），T1 成立笔数 13 → 17，6 个点变动：

| 代码 | 日期 | 方向 | 变动 | PEAK c/b | FULL c/b |
|---|---|---|---|---|---|
| sh.600020 | 2020-02-04 | 买 | 新增 | 1.5626 ✗ | 0.3948 ✓ |
| sz.000020 | 2021-02-05 | 买 | 新增 | 1.4890 ✗ | 0.7424 ✓ |
| sz.000025 | 2026-07-09 | 买 | 新增 | 1.1539 ✗ | 0.6983 ✓ |
| sh.600018 | 2024-10-08 | 卖 | 新增 | 2.5055 ✗ | 0.4855 ✓ |
| sh.600029 | 2026-02-09 | 卖 | 新增 | 1.1667 ✗ | 0.1757 ✓ |
| sh.600028 | 2020-09-28 | 买 | **丢失** | 0.6311 ✓ | 1.3910 ✗ |

**事后价格验证（决定性证据）**：

| 代码 | 日期 | 来源 | +5日 | +10日 | +20日 | 20日极值 |
|---|---|---|---|---|---|---|
| sh.600020 | 2020-02-04 | 新增买 | +5.54% | +5.54% | +5.80% | **+9.23%** |
| sz.000020 | 2021-02-05 | 新增买 | +10.05% | +9.42% | +8.04% | **+14.32%** |
| sz.000025 | 2026-07-09 | 新增买 | +4.78% | +6.60% | +15.85% | **+22.20%** |
| sh.600018 | 2024-10-08 | 新增卖 | −7.90% | −7.30% | −9.84% | **−12.22%** |
| sh.600029 | 2026-02-09 | 新增卖 | −10.01% | −18.21% | −25.81% | **−26.66%** |
| sh.600028 | 2020-09-28 | PEAK 独有买 | +1.29% | +1.03% | +3.39% | **+3.39%** |

5 个新增点全部方向正确且幅度可观；唯一丢失的 sh.600028 是所有样本中最弱的
（20 日极值仅 +3.39%，其余五点最小也在 +9%/−12% 量级），丢失它属于改善。
（`+20日` 与 `20日极值` 两列相同是正常的：该股的 20 日最高价就出在最后一根。）

**实测终值（三项叠加后，41 只日线、2019-01-01 起、QFQ）**：上表只是「换成
FULL_AREA」这一个变量单独的效果。本变更还叠加了极值严格优（D0），因此
`Debug/bsp_standard_equivalence.py` 断言的终值不是 17/49 而是：

| 档位 | 1 | 1p | 2 | 2s | 3a | 3b |
|---|---|---|---|---|---|---|
| standard + `bsp1_force_scope="bi"` | 19 | 47 | 17 | 7 | 2 | 3 |
| standard + `bsp1_force_scope="swing"`（默认） | 17 | 47 | 16 | 7 | 2 | 1 |
| legacy（锁定 `peak` + 宽松极值） | 258 | 69 | 318 | 317 | 61 | 50 |

**`2` / `2s` / `3a` 不再是「完全不变」**——这一点必须明确，否则会被误读成回归：
`chan-standard-bsp1-change` 断言这三类在 `bi`/`swing` 两档间不变，那是在 `peak`
力度下成立的性质。切到 `full_area` 后成立一买集合改变，二买/三买作为**锚点依赖**
的下游类型必然随之变动：

| 类型 | 点 | 成因 |
|---|---|---|
| T2 | sh.600025 bi63 消失 | 所锚定的一买在 swing 口径下不再是成立一买 |
| T3B | sh.600016 bi28、sh.600025 bi60 消失 | 同上（design D10 的锚点依赖传播） |

这是正确传播，不是缺陷。因此第 7 节（`bsp1_force_scope` 对照）必须把
`macd_algo` / 极值严格性 **pin 回锚点时代取值**，让它只测一个变量——已在
`Debug/bsp_standard_equivalence.py` 的 `ANCHOR_ERA_PIN` 落地并注释。

丢失成因：拆 sh.600028 bi15（b 段）的逐根 MACD 柱，负柱累计 0.27894、正柱累计 0.33875,
**正柱面积大于负柱** —— 该段是震荡式下跌。PEAK 只看最深一根柱子被骗过；FULL_AREA
累加整段面积，中间正柱削弱负柱动能，正确判出「b 段并不弱，不构成背驰」。

**替代方案**：

- **B-2** `PEAK 或 FULL_AREA 任一成立即背驰` —— 更宽松，假阳性风险上升，且两个口径的
  语义混在一起无法单独回退。否决。
- **B-3** 只在一买候选路径给 FULL_AREA 单独开关 —— 会产生「同一中枢在判定与绘图两处
  用不同力度口径」的两套结果，与已存在的「判定用中枢 vs `bsp_index` 用中枢」不一致问题
  同源。否决。

**必须接受的副作用**：`legacy` 档原本继承默认 `macd_algo`。若不在 `_BSP_PRESETS["legacy"]`
显式写回 `"peak"`，「legacy 逐笔复现改造前输出」的等价性契约会失效。
`Debug/bsp_standard_equivalence.py` 的 legacy 基线必须保持 258/69/318/317/61/50 不变。

### D2: 区段中枢的区间演化策略必须是 `shrink`（收缩取交集）

**决定**：区段中枢构建器采用「前三笔定 ZD/ZG，之后每纳入一笔取**交集**收缩」，
即 `ZD = max(所有已纳入笔的 low)`、`ZG = min(所有已纳入笔的 high)`，交集为空则中枢结束。

**理由**：在观察区段 `[seg12 起点, 候选笔)` 上对比三种策略：

| 区间演化 | start=bi88 | start=bi96 | start=bi97 | start=bi99 |
|---|---|---|---|---|
| `keep` 前三笔定死后不动 | 1 个 | 1 个 | 2 个 | 2 个 |
| `union` 并集扩张 | 1 个 | 1 个 | 1 个 | 1 个 |
| **`shrink` 交集收缩** | **2 个** | **2 个** | **2 个** | **2 个** |

现有代码是 `keep` 与 `union` 的混合：`CZS.try_add_to_end` 对多笔中枢不改区间（keep），
而 `CZS.do_combine` 做 `low=min(...)` / `high=max(...)`（union）。并集扩张正是吞并机制——
区间一旦扩宽，后续每一笔都更容易重叠，滚雪球吞到底。

`shrink` 的语义就是 `CZS.update_zs_range` 自身的定义
（`low = max(bi._low())` / `high = min(bi._high())`），也是缠论「中枢是被至少三个连续
次级别走势所重叠的部分」的严格形式。只有 `shrink` 在 4 个起点下全部稳定得到
2 个中枢 + strict 趋势成立，消除了「换个 `begin_time` 结论就变」的史实性依赖。

**已知副作用**：`shrink` 会压窄区间。start=bi88 时中枢 1 收敛为 `[10.7042, 10.7574]`，
而真实震荡范围是 10.70~11.36，上沿明显偏低。后果是 `z2.high < z1.low` 这类趋势判据
**更容易成立**，存在假阳性风险。缓解措施见 D4。

### D3: 观察区段起点取「最后一个确认线段的终点笔 + 1」，而非「其起点」

**决定**：观察区段 = `[last_sure_seg.end_bi.idx + 1, 候选笔]`。**不包含**最后确认线段本身。

**理由**：这是本轮最重要的发现 —— 两种起点规则在 5 个起点上给出**相反结论**：

| begin_time | 最后确认段 | 规则 A（段起点） | 规则 B（段终点+1） |
|---|---|---|---|
| 2018-01-01 | seg12 UP bi88-bi96 | region=bi88 **FAIL**（新低 NG） | region=bi97 **ALL-PASS** |
| 2019-01-01 | seg10 UP bi76-bi84 | region=bi76 **FAIL**（新低 NG） | region=bi85 **ALL-PASS** |
| 2020-01-01 | seg9 UP bi63-bi71 | region=bi63 **FAIL**（新低 NG） | region=bi72 **ALL-PASS** |
| 2023-01-01 | seg4 UP bi22-bi30 | region=bi22 **FAIL**（新低 NG） | region=bi31 **ALL-PASS** |
| 2025-06-01 | seg1 UP bi2-bi4 | region=bi2 ALL-PASS | region=bi5 ALL-PASS |

规则 A 的失败原因已精确定位：它把 **2024-09-12 的 8.4587（bi87）** 和
**2025-04-07 的 9.4262（bi95）** 纳入「创趋势新低」的比较范围。这两个低点属于
**上一轮价格周期**，与 2025-07 起的这轮下跌趋势无关，导致 9.7747 被判为「不是新低」:

```
规则A 比较区间 bi87..bi108
  低于 9.7747 的下跌笔: [(87, 8.4587), (95, 9.4262)]  -> 新低 NG
规则B 比较区间 bi96..bi108
  低于 9.7747 的下跌笔: []                            -> 新低 OK
```

根因是**观察区段同时承担了两个职责**：中枢构建（需要足够长的历史才能凑够 2 个中枢）
与极值比较（需要排除上一轮周期的极端值）。规则 A 为了凑中枢而拉长区段，把上一轮周期的
低点也带了进来。

规则 B 在 21 只样本上的稳健性抽查：区段中枢数 >= 2 的有 15 只、= 1 的有 6 只、= 0 的
0 只。即规则 B 下多数股票仍能凑够趋势前提所需的 2 个中枢。

**替代方案**：

- **规则 A（段起点）** —— 直觉上「回溯到上一个确认线段为止」更自然，但实测 4/5 失败，
  因为它污染了极值比较范围。否决。
- **规则 A + 独立的极值比较起点（趋势起点）** —— 即中枢构建用长区段、极值比较用短区段。
  这在语义上更正确（两个职责本就该分开），但引入两套边界，复杂度明显上升。
  列为 D5 的开放问题。

### D4: `shrink` 压窄的风险缓解

**决定**：区段中枢 SHALL 同时保留 `peak_low` / `peak_high`（全部已纳入笔的真实极值），
并对中枢区间设最小幅度约束 —— `(high - low) / mid` 低于阈值时该中枢不成立。

**理由**：`shrink` 会把区间压到几分钱的宽度（start=bi88 中枢 1 压缩到
`[10.7042, 10.7574]`，宽度 0.0532 / 中值 10.73 = 0.50%）。这种伪中枢会让
`z2.high < z1.low` 轻易成立，是 D2 假阳性风险的来源。`peak_low/peak_high` 已是
`CZS` 的现有属性（`update_zs_end` 维护），无需新增数据结构。

阈值取值待实证确定，不阻塞本变更（本变更不实现构建器，见 Non-Goals）。

### D5: 分层落地顺序

**决定**：按下列顺序推进，每层独立验证后可单独回退。

```
第 0 层  区段中枢构建器（shrink + 最小幅度约束）     独立变更
第 1 层  观察区段（规则 B：最后确认段终点+1）       依赖第 0 层
第 2 层  力度口径 PEAK → FULL_AREA（D1）           ★ 本变更
第 3 层  线段归属 / 虚段触发                        独立变更
```

**理由**：D1 与其余三层**正交**。它在现有架构下就能单独实施（改一个配置默认值 +
`legacy` 锁死 + 回归），41 只样本已证明全改善。但它**不会让 07/01 判出一买** ——
07/01 还卡在第 1、2 关。必须把这一点写进 tasks，防止实施者误以为改完力度就解决了
基准案例。

## Risks / Trade-offs

- **[FULL_AREA 在更大样本上出现假阳性]** → 本变更先在 41 只样本上锁定基线；扩展到全市场
  后若 T1 数量异常膨胀，可用 `macd_algo` 单项覆盖逐股回退（该 key 已在 `FINGERPRINT_KEYS`
  中，取值变化会使指纹失效并触发重算，无需额外代码）。
- **[legacy 等价基线被破坏]** → `_BSP_PRESETS["legacy"]` 显式写 `"macd_algo": "peak"`；
  `Debug/bsp_standard_equivalence.py` 的 legacy 基线（258/69/318/317/61/50）必须逐项不变，
  作为 CI 门禁。
- **[`bsp_index` 全量回刷成本]** → `macd_algo` 已在 `FINGERPRINT_KEYS` 中，取值变化自然使
  全部快照失效并触发重算，无需改指纹逻辑；但重算耗时需评估（41 只 × 2 档约 16s，
  全市场需分批）。
- **[D3 的规则 B 在长区段股票上凑不够 2 中枢]** → 21 只抽查中 6 只只有 1 个中枢，这些股票
  的 T1 会退化为 T1P。这是规则的保守方向（宁可少判，不做无中枢的趋势），可接受；
  若需提高覆盖率，走 D3 的「独立极值比较起点」方案。
- **[本变更只解决第 3 关，基准案例仍判不出]** → tasks 中显式标注 07/01 的验收需等前两层
  落地；本变更的验收标准是 41 只样本的 T1 从 13 变 17 且 6 个变动点方向正确。

## Migration Plan

   加 `"macd_algo": "peak"`。
