# Proposal: chan-standard-bsp1-change（单中枢背驰降级路由 + 一买力度口径走势化 + 区间套特征化）

## Why

变更 `chan-standard-bsp` 把第一类买点的趋势前提（`bsp1_trend` + `min_zs_cnt=2`）落实为标准口径后，《文档/一买一卖差异点说明.md》§4.1 的**语义污染**问题已修复——单中枢盘整背驰不再被标成 T1。但修复留下了**信号丢失**的副作用：

标准档下，一个「有非一笔中枢、离开笔突破中枢、面积背驰成立、`bs1_peak` 通过」的结构，若线段内只有一个中枢（或因两中枢未依次下移而不构成趋势），`check_bsp1_standard` 会在 `reason='trend'` 处短路，`is_target_bsp` 被置为 False，该点**既不产出 T1，也进不了 T1P**——它从系统中彻底消失。而缠论体系里这类点的正确身份恰恰是**盘整背驰**，也就是 T1P 类型本身该收的东西。T1P 现有的判定入口 `treat_pz_bsp1` 只处理「无结构中枢、最后两笔背驰」的情形，收不到这批点。

41 只日线（2019-01-01 起、QFQ）实测：趋势判定拦下 314 个一买候选，其中 161 个通过了 `bs1_peak` 与面积背驰（即「除趋势外全部合格」），86 个还通过了 DIF 背驰、142 个通过了零轴回抽。这些是本该作为盘整背驰被度量、却完全不可见的信号。

同时，量级测算暴露了一个必须显式决策的设计点：若降级点被登记为「成立」并进入 `bsp1_sure_dict`，二买/三买的锚点会随之放大 5 倍以上（2:12→61、3b:1→22），因为 `treat_bsp2`/`treat_bsp3` 以 `bsp1_sure_dict` 为锚。这会以「修 §4.1 的副作用」为名，把二买/三买的口径一起改掉，属于不可接受的连带影响。

## What Changes

- **新增降级路由 `bsp1_downgrade_to_pz`（默认 `True`）**：在 `treat_bsp1` 中，当且仅当「背驰链路本身成立（面积背驰 + `bs1_peak`）但 `check_bsp1_standard` 仅在 `trend` 条件不通过」时，把该点**以 T1P 类型登记**，而非静默丢弃。这是语义纠正（把点送回它该在的类别），不是口径放宽——T1 的判定条件一字不改。
- **降级点不进一买锚点集合（关键约束）**：降级 T1P **不写入** `bsp1_sure_dict` / `bsp1_sure_list`，因此不会被 `treat_bsp2` / `treat_bsp3_before` / `treat_bsp3_after` 当作一买锚点。二买、类二、三买的数量与构成**零变化**（实测 2:12 / 2s:4 / 3a:1 / 3b:1 完全不变）。
- **降级点携带可区分特征**：`feature_dict` 写入 `bsp1_downgrade_reason`（取值 `single_zs`：多笔中枢数不足 2；`no_trend`：有两中枢但未依次下移/上移）。下游可按此把「降级 T1P」与「无中枢笔背驰 T1P」分开统计，而无需新增类型编号（遵守前一变更的 Non-Goal）。
- **新增档位预设项**：`legacy` 档展开为 `bsp1_downgrade_to_pz=False`，保证旧行为可逐笔复现（legacy 下 `min_zs_cnt=1` + `bsp1_trend=False`，趋势几乎不拦，路由本来也近乎不触发）。
- **新增力度口径开关 `bsp1_force_scope`（默认 `"swing"`，第二部分）**：把一买背驰的 b/c 力度比较从「单笔」升级为「走势段」，修复《文档/一买一卖差异点说明.md》§4.4 的「单笔冒充次级别走势类型」（详见下方「力度口径走势化」小节）。
- **新增区间套特征开关 `bsp1_qjt`（默认 `False`，第三部分）**：在核心内为一买候选点计算「c 走势段内部是否存在次级别已确认同向一买」，结果作为**特征字段**写入 `feature_dict`（`bsp1_qjt_hit`），不改 `is_target_bsp`。修复《文档/一买一卖差异点说明.md》§4.6 的「区间套在核心未实现」（详见下方「区间套特征化」小节）。
- **不改动**：T1 的四项标准判据与短路顺序、`check_bsp1_standard` 的实现、`treat_pz_bsp1` 的既有逻辑、二买/类二/三买的任何判据与锚点口径、线段级别的判定路径（路由同时对两个层级生效，但线段级别实测无新增点）。力度口径改造只改变 `ZS.is_divergence` 的**取值窗口**，不改比较逻辑与阈值语义。区间套特征化**不改变任何买卖点的成立性**——`bsp1_qjt_hit` 只写特征、不改 `is_target_bsp`，全部六类输出逐笔不变。
- **BREAKING（下游数据）**：默认档下 `bsp_index` 的 `1p` 行从 0 增至约 52（41 只日线；采用走势段口径后的终值，单笔口径为 53），成立 T1 由 14 变为 13，存量需全量回刷。`config_fingerprint` 因新 key 自动失效，首次重算退化为全量（沿用前一变更 D11/D12 的既有机制）。区间套开关默认关闭，默认档下该部分零输出变化；开启后只新增特征列，不改行数与成立性。

## Capabilities

### New Capabilities

- `chan-bsp1-downgrade`: 单中枢背驰降级路由——降级触发条件、降级点的类型归属、锚点隔离约束、可区分特征、档位回退语义，以及它与 T1P 既有判定入口的边界划分
- `chan-bsp1-force-scope`: 一买力度口径的窗口语义——b/c 两段的窗口边界定义、`"bi"` / `"swing"` 两档取值、不支持区间计算的力度算法的降级行为，以及它与 `is_divergence` 既有单笔口径的兼容关系
- `chan-bsp1-qjt`: 一买区间套特征——c 走势段窗口的次级别映射、命中资格（同向且已确认的一买）、特征字段语义与不改成立性的约束、递归深度默认 1 层，以及它与 WebAPI L1 共振的边界划分

### Modified Capabilities

- `bsp-index`: 「日终买卖点索引」的 `1p` 行收录口径扩展——除既有「无结构中枢的笔背驰」外，还收录「有中枢但不足趋势前提、背驰链路成立」的降级点；且明确降级点不得作为二买/三买锚点，索引的 `2`/`2s`/`3a`/`3b` 行不因降级而变

## Impact

- **核心库**：`ChanAnalyse/BuySellPoint/BSPointList.py`（`treat_bsp1` 分支路由 + b/c 窗口计算，约 40 行）、`ChanAnalyse/BuySellPoint/BSPointConfig.py`（新增两个配置项）、`ChanAnalyse/ChanConfig.py`（默认值 + `legacy` 预设展开 + 指纹范围自动覆盖）、`ChanAnalyse/ZS/ZS.py`（`is_divergence` 增加可选窗口参数，默认 `None` 保持原行为）。判据实现（`BSPJudgement.py`）不改；力度算法（`Math/Metric.py`）零改动——区间版本函数已存在。区间套部分：`BSPointList.py` 增加后置特征注解（`_annotate_qjt`，挂在 `cal` 的收尾）、`CChan` 级别循环提供次级别容器引用（只读，不建立新指针图）；`ChanConfig` 默认 `bsp1_qjt=False`（**与降级/力度口径不同，这是默认关闭的特征开关**）。
- **力度口径改造**：`ZS.is_divergence` 新增 `b_window` / `c_window` 可选参数（默认 `None` = 现有单笔行为，逐字节向后兼容）；`treat_bsp1` 负责计算窗口并传入。b 窗口 = 上一中枢结束笔+1 ~ `zs.bi_in`（无上一中枢则取线段首笔）；c 窗口 = `zs.end_bi`+1 ~ `seg.end_bi`。span 口径只覆盖 `Metric.py` 已有区间函数的 8 种算法，成交量/换手率类 5 种自动退回单笔口径并在 feature 标注 `bi_fallback`。
- **下游数据**：PG `bsp_index` 的 `1p` 行需按新口径全量回刷；`WebAPI/performance_store.py` 中类二/一买的分母说明需补一句「`1p` 现含降级点，可按 `bsp1_downgrade_reason` 拆分」。`WebAPI/bsp_ladder.py` 的 L1/L3 统计不按类型缩放，无需改阈值。
- **前端**：`1p` 标签已存在；买卖点页筛选与 K 线覆盖层无需改代码。若需区分降级点，需透出 feature（非本次范围）。
- **文档**：`文档/一买一卖差异点说明.md` §4.1、§4.4、§4.6 与 §七/§八 需回标本变更；`文档/缠论策略.md` 3.6/第 11 章配置表补 `bsp1_downgrade_to_pz`、`bsp1_force_scope` 与 `bsp1_qjt`；`Document/README.md` 买卖点参数段补这三项。
- **验证**：`Debug/bsp_standard_equivalence.py` 增加降级开关的对照行，并把 `legacy` 等价基线保持不变（回退路径必须逐笔一致）；增加区间套开关对照——开启 `bsp1_qjt` 后六类数量与关闭时逐类一致、命中点全部落在 `bsp1_list` 家族且带 `bsp1_qjt_hit` 字段。

## 降级触发的收紧口径（2026-10-24 补）

初稿的触发条件「背驰链路成立（面积背驰 + `bs1_peak`）+ `reason == 'trend'`」经实测存在两处漏洞，已收紧为「背驰**实证** + 极值判据 + 趋势外其余标准判据**全检**通过」（详见 design D1-a / D1-b）：

- **背驰不能取空真**：`divergence_rate > 100`（显式关闭背驰判据）时 `is_divergence` 无条件返回 `True`，这是放行语义，不能当作「该点确实背驰」的证据，否则无力度衰竭的点会被贴上「盘整背驰」标签。
- **`reason == 'trend'` 不等于「其余三项通过」**：`check_bsp1_standard` 短路返回，报出 `trend` 时新低/DIF/零轴根本没跑，状态是「未知」。需以关闭趋势的配置重跑一次全检。

41 只日线（2019-01-01 起、QFQ、standard 档）实测漏斗：候选 573 → `reason=='trend'` 314 → 面积背驰 168 → `bs1_peak` 通过 142 → **补全检后 53**。53 与本变更既定的期望值精确一致，说明收紧方向正确；若按初稿口径实现将产出 142 个降级点，tasks 的基线断言必然失败。

## 力度口径走势化（§4.4，2026-10-24 并入）

《文档/一买一卖差异点说明.md》§4.4 记录的问题——「比较对象是进入中枢的那一笔，不是进入中枢的次级别走势」——前一变更标为**部分修复**（靠线段级别承担次级别语义）。但笔级别路径仍是单笔：`ZS.is_divergence` 取 `get_bi_in()`（紧邻中枢开始前的那一笔）与 `seg.end_bi`（离开笔）比较。当离开中枢后走了多笔才见底时，单笔口径只看最后一笔，会误判「力度衰竭」。

**为什么并进本变更而非另开一个**：降级路由的触发条件 `diver_proven` 直接来自 `is_divergence` 的返回值。两者改同一处语义，分两个变更会各自测各自的基线、合并时才发现数字互相污染。并入后 T1 与 T1P 的漏斗在同一套口径下锁定。

**改动内容**：

- 新增 `bsp1_force_scope`，取值 `"bi"` / `"swing"`，默认 `"swing"`；`legacy` 档展开为 `"bi"`。
- `ZS.is_divergence(config, out_bi=None, b_window=None, c_window=None)` 新增两个可选参数，默认 `None` 时行为与改造前**逐字节一致**。
- `treat_bsp1` 计算窗口：b = 上一中枢结束+1 ~ `zs.bi_in`（无上一中枢取线段首笔）；c = `zs.end_bi`+1 ~ `seg.end_bi`。
- span 力度用 `Metric.py` 已有的区间版本（`cal_macd_peak` / `cal_macd_area` / `cal_macd_diff_peak` 等 8 种），把窗口内所有笔的 `klc_lst` 串联后按 `begin_idx`/`end_idx` 取值。

**为什么用区间聚合而不是「逐笔取 max」**：实测两者结果几乎相同（41 只日线上 20 vs 19），但区间聚合的语义就是「这一整段的力度」，无需论证「为什么取 max 而不是 sum」；且复用已有区间函数，不新增算法。

**为什么不改 `check_new_extreme` 之类**：§4.4 只涉及 b/c 力度比较，其余四项判据不动。

**实测影响**（41 只日线，2019-01-01 起、QFQ、standard 档）：

| 指标 | 单笔口径（改造前） | 区间聚合（改造后） | 变化 |
|---|---|---|---|
| 成立 T1 | 14 | 13 | -1 |
| 降级 T1P | 53 | 52 | -1 |

唯一翻转的样本是 `sh.600016 bi=31`（买点）：离开段含 3 笔，单笔 `r=0.837 ≤ 0.9` 判背驰，整段 `r=1.746 > 0.9` 判不背驰——**离开中枢后每一笔都在创新低，整段空头动能在增强**，单笔口径只看了最后一笔 0.0225，误判为衰竭。这正是 §4.4 描述的缺陷。

**为什么不改 §4.5（零轴回抽）**：§4.5 涉及 `check_zero_axis` 的判据重建（零轴回抽的深度阈值、b/c 两段独立回抽），与 §4.4 只改取值窗口的性质不同；本次明确不做，另案评估。

**回退**：`bsp1_force_scope="bi"`（细粒度，只回退力度口径）或 `bsp_preset="legacy"`（粗粒度，legacy 下 `divergence_rate=inf` 根本不计算 metric，天然回归）。两者互不干扰。

## 区间套特征化（§4.6，2026-10-24 并入）

《文档/一买一卖差异点说明.md》§4.6 记录的问题——「区间套（要素 F）在核心未实现，仅 WebAPI 层有时间窗近似」——前一变更标为**未修复**。本次把它落进核心，但以**特征字段**而非硬判据的形态，且**与 §4.4 的力度口径走势化共享同一套 c 走势段窗口**。

**为什么并进本变更而非另开一个**：区间套的判定窗口是「一买 c 走势段的次级别映射」，而 §4.4 的 `bsp1_force_scope="swing"` 恰好已经在 `treat_bsp1` 内建立「c 段 = `zs.end_bi`+1 ~ `seg.end_bi` 的走势段」这一窗口对象。分两个变更会重复定义同一窗口、两处漂移。并入后窗口语义单点锁定（详见 design D7）。

**改动内容**：

- 新增 `bsp1_qjt`（默认 **`False`**——特征开关先观测、不改变任何输出），`legacy` 档显式展开为 `False`；进 `FINGERPRINT_KEYS`。
- 判定：对 `bsp1_list` 家族的每个一买候选点，取其 c 走势段映射到次级别的结构区间，查询次级别 `bs_point_lst.bsp1_sure_list` 中是否存在**同向、已确认**的 T1；命中写 `feature_dict['bsp1_qjt_hit']=True` 及 `bsp1_qjt_sub_idx`（命中点笔索引）。
- 递归深度 `bsp1_qjt_depth` 默认 1 层：多层递归会成倍放大「子级确认滞后」的步进/批量口径分叉（见 design D8 的示例），默认收敛一层。
- **WebAPI L1 共振（`bsp_ladder.cal_l1_resonance`）保留，不删除**：二者不是同一功能——内核 qjt 是一买候选点的成立性证据（仅 T1 家族、结构窗口、特征随点持久）；L1 是全类型未确认点的跨级别佐证标签（二买/三买候选没有「c 段」概念，时间窗是唯一可行口径，且是已归档 `bsp-ladder-change` 的 ladder 落库列契约）。边界说明写入文档。

**为什么先做特征、不做硬判据**：区间套硬判据要求「子级同向 T1 已确认」，而子级确认天然滞后于父级候选点产生（父级线段确认依赖子级之后的 K 线）——硬判据在步进模式下会系统性漏判、破坏「批量与步进终态一致」的既有不变量。先以特征落地，等命中率数据支持后再另案升级为判据（届时与 §4.9 延迟确认合流设计）。

**回退**：`bsp1_qjt=False`（默认即关）。开启时也只增加特征列，无任何行数或成立性变化。
