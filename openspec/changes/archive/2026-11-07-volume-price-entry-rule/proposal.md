# Proposal: volume-price-entry-rule（量价三段式买点规则 + 回测验证）

## Why

用户定义了一套日线级别的量价买点规则（蓄势期 → A 日放量启动 → 调整期缩量回踩 → B 日分钟级放量触发买入），需要用程序回测验证其有效性。规则经多轮讨论已定稿（V3），量化公式完整闭环，但当前仓库没有可执行该规则、评估其绩效的回测框架。在投入实盘监控前，必须先用历史数据回答「这套规则是否具有正期望」。

## What Changes

- 新增**信号判定状态机**：按 V3 规则从日线识别候选信号（蓄势期 → A 日 → 调整期 → B 日触发），纯量价代数，不调用 CChan 缠论计算内核
- 新增**分钟级盘中触发引擎**：B 日逐 5 分钟 bar 扫描（涨幅区间 + 分钟放量 + 虚拟全天量 VP 口径）；无分钟数据时退化日线收盘版
- 新增**虚拟量（预测量能）计算**：分时量能分布校正法（F(t) 为该股近 60 日同时刻累计占比中位数），弃用线性外推
- 新增**回测绩效引擎**：五口径离场（止损 / T+5 / T+10 / T+20 / MA5/MA10 趋势跟随）、参数敏感性扫描、基准对照（随机买入 + 等权）、样本分桶统计（Spring / 基底形态 / 分钟版 vs 日线版）
- 新增**数据灌取管道**：日线筛门下推 DuckDB SQL；分钟数据按候选股惰性落库（复用 KLineStore / download_kl 幂等写入模式）

## Capabilities

### New Capabilities

- `entry-signal-rule`: 量价三段式买点规则的信号判定规范——蓄势期基底（区间盒 + 量能均值门）、A 日放量启动、调整期（量能峰 P + 回踩段 D' + Spring 豁免）、B 日分钟级触发的全部量化条件
- `entry-backtest`: 回测验证框架规范——数据口径（分钟版优先、日线退化版兜底）、离场规则、绩效指标、敏感性扫描与防过拟合纪律、性能架构（DuckDB 下推 + 分钟数据惰性落库）

### Modified Capabilities

（无——本变更不改动任何现有能力的需求。缠论计算内核、DuckDB 持久化、Web 前后端均不受影响）

## Impact

- **新增代码**（不改动现有模块）：信号状态机、虚拟量计算、回测引擎、绩效报表，预计落在 `Debug/` 或独立脚本目录，复用 `ChanAnalyse/DataAPI/KLineStore.py`、`IngestUtil.py` 的现有数据设施
- **数据**：`Data/kl_store.duckdb` 增补候选股的 5 分钟数据（经 akshare 东财分钟接口灌入，复用幂等写入）
- **不触碰**：`CChan` / `CBiList` / `CSegListChan` / `CZSList` / `CBSPointList` 计算逻辑（遵守仓库既有约定）、`WebAPI/`、`Front/`、PG 业务表
- **外部依赖**：akshare 分钟接口（东财，历史深度约一年余，决定分钟版回测时间窗）
