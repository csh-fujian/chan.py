# Proposal: chan-standard-bsp2-change（二买/类二候选确认体系 —— 五轴阶梯接入）

## Why

《文档/二买二卖差异点说明.md》§4.4（回调为单笔、线段级别严格语义零下游消费）与 §4.7（无事后价格确认）在 `chan-standard-bsp` 中被标记为部分修复/未修复。用户确认策略侧将把 T2 当入场/确认信号使用，当前 T2 的「确认」仅是重算稳定性代理（`is_sure` 水位线），没有价格/结构证据——批量模式下 15 个 T2 的 `is_sure` 全为 True 是虚拟笔补全副产物，对把它当确认信号用的下游是真实风险。同时 `chan-bsp-ladder-change`（进行中）已把三轴阶梯基建建好，但明确将 T2/2s/3a/3b 排除在外（ladder 置 NULL，过渡方案 A），为逐类型接入预留了槽位。

## What Changes

- **T2/2s 接入多轴阶梯（非一买类型第一个接入者）**：候选点（`is_sure=False` 或未达 L4 的 T2/T2S）携带五轴独立证据组合，落库 `bsp_index.ladder`，终结过渡方案 A 的 NULL 语义（T2/T2S 部分；T3A/T3B 仍留 NULL 待后续）
- **五轴体系**（本轮探索会话逐条确认）：
  - 进度轴：T2 判据链 ①一买成立（`bsp1_sure_dict`）②+2 笔回调存在 ③不破一买极值（恒过）④回撤率 ≤ `max_bs2_rate` ⑤`bsp2_retrace_zs` 中枢关联（可选），两档划分（仿 T1 的 ceil 折半）
  - 佐证轴（§4.4 路径 B）：三档 L2-3/L2-2/L2-1，子级别（如日线 T2 → 30 分钟）同向已确认/候选/末端分型，结构映射窗口 = `bsp2_bi` 所在笔窗口（沿用 T1 口径）
  - 确认轴（§4.7）：三档制 —— 后续笔突破 `break_bi` 高点 / 收复一半以上 / 未动；窗口走完未突破 → **降级标签（终态），不撤销 T2 行**（与 T1 候选不删除口径一致）
  - 分型轴（2.4）：`bsp2_bi` 末端分型强弱，复用 `fractal_strength` 纯只读分级
  - 时间轴（2.6，独立成轴）：回调速度比 `v = (amp(bsp2_bi)/amp(break_bi)) / (bars(bsp2_bi)/bars(break_bi))`，三档 v ≤ 0.5 / 0.5~1.0 / > 1.0（急涨缓跌=衰竭=强档）；用速度比而非原始时间比，避免与判据④回撤率正相关
- **明确排除**（用户决策）：量能特征（2.2）与 ML 打分（2.5）**不加入** T2 候选判断
- **T2 阶梯语法独立定义**：轴前缀不复用 T1 的 L 编号（L4 已被「已确认」占用且语义不可动），采用语义前缀（如 `P1|S3|K3|C3|T3`，`confirmed` 保持单值）；T1 家族语法不动，靠 bsp_type 区分
- **确认轴终态单向性**：未突破 → 已突破可翻，终态降级不再动；翻转重刷逻辑按单向终态设计（比 ladder change 现有 False→True 多一种翻不动的情况）
- **时间轴可双向翻转**：候选未定型时 `bsp2_bi` 延长会使档位滑动（强→中→弱），翻转重刷验收须覆盖降档场景
- **`bsp_index.ladder` 再扩容**：五轴组合约 20~26 字符，`VARCHAR(16)` → `VARCHAR(32)`，走 `bsp_store._ensure_tables()` 惰性 DDL + `update-win.sql` 幂等追加；存量 T2/2s 行从 NULL 回刷为组合值
- **`seg_bs_point_lst` 下游暴露评估**：仅作为本变更的前置调研任务（统计线段级别 T2 与笔级别 T2 的重合度），不默认暴露到 WebAPI/bsp_index——暴露与否待调研结论（见待定项）
- **前置实证任务**：41 只日线统计——①确认轴三档各自占比与「下两笔是否突破」的时点后移量；②时间轴三档 × 突破结果的交叉判别力（阈值 0.5/1.0 的校验依据）；③线段级别/笔级别 T2 重合度。实证结论决定两个待定项
- **文档回标**：《文档/二买二卖差异点说明.md》§4.4/§4.7 状态更新；`Document/README.md` 补 T2 阶梯参数段
- **范围限定**：不改 `treat_bsp2`/`treat_bsp2s` 的成立判据（判据链零改动，五轴全部是「证据标注不改成立性」，与 ladder change 同一原则）；T2S 类二沿用同一轴体系（`bsp2s_bi` 对应替换）；不改 `bsp_is_sure` 水位线口径；T3A/T3B 不动
- **依赖时序**：须在 `chan-bsp-ladder-change` 归档后实施（复用其三轴框架、翻转重刷机制、`ladder` 扩容先例）；与 `chan-bsp1-strict-extreme` 建议串行（同改 `BuySellPoint` 核心区域，避免验证基线互踩）

## Capabilities

### New Capabilities

- `chan-bsp2-ladder`: 二买/类二候选确认的五轴阶梯契约——五轴定义（进度/佐证/确认/分型/时间）、各轴分档、T2 独立语法与 confirmed 单值、确认轴终态单向性、时间轴双向翻转、量能与 ML 的显式排除语义、非一买类型接入阶梯的过渡终结（T2/T2S 部分）
- `chan-bsp2-confirm`: 二买的事后价格确认契约——确认对象（`break_bi` 高点与 `bsp2_bi` 起点高点两级阈值）、三档、降级不撤销、确认窗口（待定项，实证后定）、翻转重刷的单向终态设计

### Modified Capabilities

- `bsp-index`: ladder 列语义扩展（T2/T2S 从 NULL 变为五轴组合值；`VARCHAR(16)` → `VARCHAR(32)`；存量行回刷口径）

## Impact

- **WebAPI 层**：`bsp_ladder.py`（五轴推导、T2 语法、翻转逻辑）、`bsp_progress.py`（T2 判据链进度映射）、`incremental_engine.py`（T2 候选翻转重刷、fingerprint bump）、`bsp_store.py`（ladder 扩容惰性 DDL）、`serializer.py`（T2 候选阶梯序列化）
- **验证基建**：`Debug/` 新增实证脚本（确认轴占比/时间轴判别力/线段笔级别重合度三统计）+ 翻转用例（终态单向、时间轴降档）
- **数据库**：`bsp_index.ladder` 扩容（`update-win.sql` 幂等追加，Windows 机器运行）+ 存量 T2/2s 行回刷
- **文档**：《文档/二买二卖差异点说明.md》§4.4/§4.7 回标、`Document/README.md` 参数段、`文档/缠论策略.md`（判据语义不变的确认性说明）
- **不改动**：`ChanAnalyse/BuySellPoint/BSPointList.py` 成立判据、`bsp_sure.py` 水位线口径、T1 家族阶梯语法与行为
- **下游**：策略侧（用户已确认 T2 为入场/确认信号）获得按轴取门槛的能力；策略消费契约本身为待定项

## 待定项（实证后定，提案阶段标注）

1. **确认窗口长度**：看下一笔还是下两笔（影响确认轴时效与信号后移量）
2. **策略消费契约**：默认门槛取「确认轴最高档」「仅 confirmed」还是其他组合——用户明确「暂无法定义」，依赖实证数据（三档占比+时点后移）摆到面前后再选
3. **时间轴阈值**：0.5 / 1.0 为初始拍定值，交叉判别力统计后校准；若强档突破率不显著高于弱档，时间轴降级为纯 feature 不成轴
4. **`seg_bs_point_lst` 是否暴露**：取决于线段/笔级别 T2 重合度统计——重合度高则暴露收益低，维持零消费现状
